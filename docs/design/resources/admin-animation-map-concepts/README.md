# AKRA Admin Animation Map Concepts

이 디렉터리는 현재 `/admin/akra` 운영 자산을 교체하지 않는 **선택 전 reference-only 갤러리**입니다.

- 대상: PC 관리자 웹, 기준 뷰포트 `1920×1080`, 상위 검증 `2560×1440`
- 비교 축: 가구 색상 변형이 아니라 역할 구역, 좌석 관계, 이동 경로의 토폴로지
- 공통 불변 요소: 기존 아이소메트릭 카메라, dark navy/cyan + warm amber/wood, HTML에 합성한 동일한 5명 roster
- 캐릭터: 런타임에서 쓰는 `gamebaljeonguk_atlas_128x192.png`를 HTML에서 실제 CSS sprite로 합성
- 모션: 장식성 무한 이동 대신 버튼으로 한 번 실행되는 `standby → vacant assigned desk` 전환 1개. 각 경로는 보이는 출입구·계단·통로를 지난다.
- 접근성: 키보드 탭/숫자/방향키, 포커스 표시, `prefers-reduced-motion`, 이미지 대체 텍스트

## 확인 방법

저장소 루트에서 정적 서버를 실행합니다.

```bash
python3 -m http.server 18446 --bind 127.0.0.1 --directory .
```

브라우저에서 다음 주소를 엽니다.

```text
http://127.0.0.1:18446/docs/design/resources/admin-animation-map-concepts/index.html
```

안별 deep link는 `#a`, `#b`, `#c`, `#d`, `#e`입니다. 초기 화면은 A안이며, 갤러리는 사용자의 선택을 먼저 받기 위해 특정 안을 추천 상태로 표시하지 않습니다.

## 정성 루브릭

오른쪽 패널의 `강점 / 보통 / 제약`은 실측 점수나 운영 지표가 아닙니다. 2026-07-14 디자인 검토를 위한 다음 휴리스틱의 정성 분류이며, 특정 안을 자동 선정하지 않습니다.

- 스캔성: 역할 구역과 좌석 관계가 한눈에 구분되는가
- 동선: 보이는 출입구와 통로로 배정 좌석에 도달하는가
- 확장성: 좌석·구역을 추가해도 핵심 구조가 유지되는가
- 게임 감각: 상태 변화가 공간의 초점과 장면성으로 읽히는가
- 구현 용이성: anchor, hit area, z-order를 결정적으로 관리하기 쉬운가

생성 배경 속 가구의 세부 수량은 이미지 모델의 변동이 포함된 **비권위적 공간 무드**입니다. 통제된 비교 대상은 HTML에 합성한 기존 atlas 캐릭터 5명, 같은 상태, 같은 카메라와 각 안의 역할·동선 토폴로지입니다. 최종안으로 승격할 때는 선택한 구조를 결정적 좌표와 정확한 가구 수로 다시 제작해야 합니다.

## 런타임 승격 주의

생성 이미지에는 비교를 위해 가구가 포함되어 있습니다. 생성 결과의 좌석·소파 수량은 런타임 계약이 아닙니다. 현재 런타임은 배경 위에 가구와 캐릭터를 Pixi로 별도 합성하므로, 이미지만 `assets/admin/graphics/final-draft-map-sprite.png`로 교체하면 가구가 중복됩니다.

최종안 선택 뒤 별도 작업 단위에서 다음을 함께 정리해야 합니다.

1. 선택한 배경의 가구 bake/overlay 전략 통일
2. 좌석·standby·event-log anchor를 하나의 manifest로 통합
3. Pixi z-order를 가구/캐릭터 단위로 정렬
4. CSS hit area와 canvas 좌표의 단일 소스화
5. 1280×800, 1600×1000, 1920×1080, 2560×1440 시각 회귀 검증

생성 방식과 해시는 [provenance.json](./provenance.json), 사용 프롬프트는 [PROMPTS.md](./PROMPTS.md)에 기록했습니다.

기존 저장소 자산을 참조한 파생 이미지의 생성과 이 공개 저장소에서의 표시·push는 저장소 소유자의 이번 요청으로 승인되었습니다. 이는 이번 저장소 범위의 공개 검토를 허용한 기록이며, 제3자의 후속 재사용·재배포 라이선스를 부여하거나 원천 권리의 chain of title을 별도로 보증하지 않습니다.
