# Desktop 로컬 연결 진단 (A10 첫 범위)

사이드바 아래 연결 상태를 누르면 **로컬 연결 진단**이 열린다. 로컬 Gateway 연결 상태를 수집하고,
수집·제외·누락 목록과 정제된 JSON을 검토한 뒤 시스템 저장 창에서 파일을 고른다.
Gateway에 연결되지 않아도 수집과 저장이 가능하다. 저장 취소와 파일 쓰기 실패는 별도로 표시한다.
저장 전 네트워크 요청, 이슈 게시, Vault 열람, 모델 호출은 없다.

## 담기는 항목

- Desktop/Electron/Node 버전과 OS 종류. Gateway/Codex 버전은 renderer가 **마지막으로 관측한 값**이며,
  아직 관측하지 못했거나 버전 형식이 아니면 null과 누락 이유를 남긴다.
- 현재 창의 로컬 Gateway 연결 상태, 통로 종류(named pipe/Unix socket), 허용된 오류 코드, 재시도 간격.
  자유 형식의 오류 설명과 실제 연결 경로는 수집하지 않는다.
- 검토 사본마다 생성한 `diagnosticId`. 이것은 **내보내기 사본의 ID**이며 Gateway 요청 ID가 아니다.
- 기존 Rust trace 파일의 최근 64 KiB에서 Gateway 메타데이터 최대 40건.
  시각·등급·고정 구분과 올바른 UUID 형식의 `correlation_id`/`op_id`만 복사한다.
  전체 메시지·오류·본문·경로·인증 필드와 모르는 필드는 버린다. 로그가 없으면 새 기록을 켜지 않는다.

trace 파일은 `AKRA_TRACE_FILE`에 명시된 파일 또는 Desktop 시작 폴더의
`.akra/runtime/log/akra-trace.jsonl.YYYY-MM-DD[.N]` 중 가장 최근 파일 하나이다.
하위 폴더나 다른 실행 폴더를 탐색하지 않는다. 현재 Gateway와 다른 프로세스의 기록일 수 있으므로
동일 연결의 로그라고 단정하지 않는다. 빈 로그, 미존재, 읽기 실패, 수집 한도 적용을 구분한다.
심볼릭 링크·일반 파일이 아닌 경로·다중 하드 링크 파일은 거절한다.

## 검토 사본과 저장

정제는 main에서 수행하고 renderer에는 정제 사본만 보낸다. 저장 요청은 사본 ID만 보내며,
main이 보유한 **미리보기와 동일한 UTF-8 바이트**를 저장한다. 사용자 선택 후 같은 디렉터리의
임시 파일에 쓴 뒤 교체하므로 연결이나 로그가 변해도 저장 내용은 바뀌지 않는다.
다른 창의 사본 ID, 새 미리보기로 교체된 ID, 닫거나 재로드한 창의 사본은 저장하지 않는다.

이 범위는 로컬 Gateway 연결 실패용이다. 이슈 게시, 지원 센터 전송, Vault 원문 복원,
로그 기록 설정 변경, 모든 작업/프로세스의 자동 수집은 포함하지 않는다.

## 검증

- `desktop/test/diagnostics.test.ts`: 민감값 canary, 로그 한도와 미존재/실패, 오프라인,
  동일 바이트 저장, 저장 취소/실패, 창별 사본 격리와 재로드 무효화, 원자적 파일 저장.
- `desktop/test/e2e/diagnostics.mjs`: 폐기 가능한 프로필의 실제 Electron/preload/main에서
  Gateway 미접속 상태로 미리보기와 저장 경로를 실행한다. 시스템 저장 창의 응답만 fixture로 대체하고,
  실제 파일 쓰기·오류를 확인한다. 실제 OS 저장 창 클릭 자체는 자동 검증하지 않는다.
