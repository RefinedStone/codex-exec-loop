# 다음 턴 입력 예약 (A06-1)

진행 중인 대화에서 **다음 턴 예약**은 입력을 현재 턴에 steer하지 않고 창 메모리에 저장한다.
기존 보내기/추가 지시는 즉시 보낸다. 예약 목록에서 아직 전송하지 않은 항목을 수정·삭제하거나
위아래로 옮길 수 있다. 한 대화에 최대 20개, 항목당 최대 32,000자를 보관한다.

예약은 DesktopSession별로 독립적이므로 서로 다른 host의 같은 thread ID를 섞지 않는다.
현재 열린 쓰기 가능한 대화에서만 자동으로 진행하며, 현재 턴의 정확한 completed 알림 뒤
하나를 turn/start한다. 접수된 새 턴 ID의 완료를 기다린 후 다음 항목을 보낸다. 접수 응답과
완료 알림 순서가 바뀌거나 완료 알림이 중복돼도 같은 항목을 다시 보내지 않는다.

| 상황 | 예약 처리 |
| --- | --- |
| 정상 완료 | 다음 예약 하나를 전송한다. |
| 사용자 중단·턴 실패/중단 | 예약을 보류하며 명시적인 ‘예약 계속’이 필요하다. 중단과 정상 완료가 겹쳐도 자동 진행하지 않는다. |
| 대화 전환·재연결 | 원래 대화의 목록을 보관하고 보류한다. 다시 열었을 때 자동 재개하지 않는다. |
| 응답 유실·오류·20초 시간 초과 | 결과 불명으로 보류하며 자동 재전송하지 않는다. 실제 대화 기록을 확인한 뒤 목록에서 지운다. 미결 RPC는 응답 또는 연결 재설정 전까지 새 전송을 막는다. |
| 창 종료·리로드 | 예약을 폐기한다. 디스크·브라우저 저장소에 보존하지 않는다. |

예약은 사용자 입력이며 A05의 자동 후속 실행과 독립적이다. 모델·추론 설정은 A06-2의 별도
범위다. 영속 예약, 서버 측 요청 멱등 키와 재시작 후 결과 조회는 이번 구현에 포함하지 않는다.

단위 검증은 `nextTurnQueue.test.ts`, 실제 세션 전송 경계는 `sessionInput.test.ts`, 화면은
`test/e2e/next-turn-queue.mjs`의 합성 Gateway를 사용한다. 실제 모델 턴을 보내지 않는다.
