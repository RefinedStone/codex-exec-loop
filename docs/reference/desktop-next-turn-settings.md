# Desktop 다음 턴 모델·추론 설정

대화 입력창의 **다음 턴 설정**에서 현재 서버가 확인한 대화 설정과 아직 전송하지 않은
모델·추론 수준을 따로 볼 수 있습니다. 지원 모델과 추론 수준은 연결한 호스트의
`model/list`를 페이지 끝까지 읽어 표시합니다. 모델 이름이나 추론 수준을 클라이언트에
고정하지 않습니다.

- 기본 상태는 **현재 설정 상속**입니다. 이때 새 턴 요청에 모델·추론 필드를 추가하지 않습니다.
- 모델을 선택하면 그 모델의 기본 추론 수준도 함께 선택하며, 지원 목록 안에서 바꿀 수 있습니다.
- 대기 설정은 다음 **새 턴**을 보낼 때 적용됩니다. 진행 중인 턴에 추가 지시를 보내는
  `turn/steer`에는 포함하지 않으며, 예약 입력도 같은 새 턴 전송 경로를 사용합니다.
- app-server의 계약상 한 번 적용한 모델·추론 설정은 그 이후 턴에도 이어집니다.
  성공 응답 이후 소비한 대기 설정은 상속 상태로 돌아갑니다. 그 사이 사용자가 새로 바꾼
  대기 설정은 지우지 않습니다.
- 현재 대화 설정은 `thread/start`, `thread/resume`, `thread/read` 및
  `thread/settings/updated`에서 확인합니다. 전송한 값만으로 서버 적용값을 추정하지 않으며,
  이 값은 각 모델 응답의 실제 실행 모델을 측정한 telemetry가 아닙니다.

## 실패와 격리

모델 목록을 모르는 서버, 응답 시간 초과, 잘못된 페이지, 반복 cursor는 조회 실패로
표시합니다. 목록이 갱신되어 대기 설정이 지원 범위에서 빠지면 임의로 다른 모델을 고르지
않고 전송 전에 보류합니다. 예약 입력도 이때 전송 전 상태를 유지하며, 설정을 고치거나
상속으로 되돌린 뒤 **예약 계속**으로 이어갈 수 있습니다.

목록을 확인할 수 없어도 현재 설정 상속은 사용할 수 있습니다. 늦게 도착한 목록이나
이전 접속의 응답은 새 접속의 상태를 바꾸지 않습니다. 설정은 창의 메모리에서 호스트별
세션과 대화 ID에 나누어 보관하므로 다른 대화·호스트에 옮겨 적용하지 않습니다.

이 기능은 모델·추론 필드만 다루며 권한, 승인 정책, sandbox 설정을 바꾸지 않습니다.
회귀 검사는 합성 응답과 fake Gateway를 사용하며 실제 모델을 호출하지 않습니다.
