## 한 줄 요약

Akra Desktop 에는 macOS 데스크톱 앱이면 기본으로 있는 동작이 없다: 확대와 축소, 뒤로 가기, 오른쪽 클릭 메뉴,
창 크기 기억, 턴 완료 알림. 이 문서는 Codex 앱, Orca, OmO Desktop 과 비교한 차이를 목록으로 적고, 고칠 순서를
정한다.

## 범위

- 대상은 `desktop/` (Electron 앱) 이다. TUI 와 Admin 은 다루지 않는다.
- 단축키는 일부이다. 목록의 대부분은 단축키가 아닌 사용성이다.
- 다른 제품의 코드를 옮기지 않는다. 동작만 우리 말로 적는다.
- 대화 상태와 판정이 필요한 항목은 kernel 이나 Gateway 를 거친다 (plan 18). Desktop 은 그리기만 한다.

## 2. Akra 의 현재 상태 (2026-11-18)

있는 것:

- 단축키 ⌘K, ⌘N, ⌘B, ⌘\\, ⌘J 와 단축키 창 (`desktop/src/renderer/views/Views.tsx`).
- 사이드바의 미읽음 표시, 진행 중 표시, 승인 대기 표시 (`sidebar/threadStatus.ts`).
- 턴 답 복사 버튼, "맨 아래로" 버튼, 계획 띠, 컨텍스트 사용량 고리.
- 변경 패널: 파일과 hunk 단위 stage 와 버리기, push, PR 만들기. 터미널, 브라우저 패널, 업무 패널.
- dot 답의 OS 알림 (`views/dotNotify.ts`).

없는 것과 원인:

- **⌘+ / ⌘− / ⌘0:** 앱 메뉴(`desktop/src/main/index.ts` 의 `installApplicationMenu`)가 기본 메뉴를 바꾼다.
  "보기" 메뉴에 `zoomIn`, `zoomOut`, `resetZoom` 이 없다. Electron 은 단축키를 메뉴에서 받으므로 단축키도 없다.
- **⌘ + 휠:** Electron 은 `zoom-changed` 이벤트만 보낸다. 앱이 처리하지 않는다.
- **뒤로 가기:** 보기 상태(`session/uiStore.ts` 의 `view`)는 값 하나이다. 이동 기록이 없다. 마우스 버튼 4·5 를
  받는 곳도 없다.
- **글자 크기:** `design/tokens.css` 에 고정되어 있다. 앱 13px, 대화 14px, 코드 12px, 보조 글자 11–12px 이다.
- **오른쪽 클릭:** `context-menu` 처리가 없다. 입력창에서 붙여넣기 메뉴와 맞춤법 제안이 나오지 않는다.
- **창:** 크기와 위치를 기억하지 않는다. 실제 앱은 기본 제목 막대를 쓴다 (블루프린트만 `hiddenInset`).
- **입력창:** 이미지 붙여넣기, 파일 끌어 놓기, `@` 파일, `/` 명령, 이전 프롬프트 불러오기, 모델 선택이 없다.
  초안은 메모리에만 있어서 재시작하면 없어진다.
- **목록과 설정:** 스레드 이름 바꾸기, 고정, 보관이 없다. 설정 화면이 없다. 대화 안 찾기(⌘F)가 없다.

| H4 | 엿보기: 현재 스레드를 떠나지 않고 다른 스레드의 마지막 대화를 본다. "열기"와 "닫기" | ✓ | – | P2 |
| H5 | 고정 상태를 kernel 이 저장한다. TUI 와 Desktop 이 같은 고정 스레드를 보인다 (L1 의 고정) | ✓ core 에 저장 | – | P1 |
| H6 | 업데이트: Desktop 과 데몬의 버전을 따로 보인다. "작업은 계속된다"를 말한다. 확인이 성공했을 때만 "최신"을 보인다. "새 기능" 화면 | ✓ | – | P2 |
| H7 | 앱 안 피드백: 초안과 스크린샷을 검토 창에 보인다. 사용자가 보내기를 누르기 전에는 보내지 않는다 | ✓ | – | P2 |

- H1 의 이유 줄은 Akra 만 할 수 있다. Herdr 는 에이전트의 자기 보고를 읽는다. Akra 는 kernel 이 원인을 안다.
  판정과 이유는 plan 23 의 주의 항목 목록이 준다. Desktop 은 이름과 줄만 그린다.
- H2 의 현재 상태: 단축키 처리(`views/Views.tsx` 의 `useShortcuts`), 단축키 창(`ShortcutsDialog`), 앱 메뉴
  (`main/index.ts`)가 같은 동작을 각자 적는다.
- H7 은 S6 (진단 묶음) 과 함께 한다. Akra 는 공개 저장소이므로 보내는 곳은 GitHub issue 초안이다.

## 4. 하지 않는 것

- 음성 받아쓰기, 떠 있는 pet 오버레이, 여러 모델에 같은 프롬프트 보내기, 칸반 보드, 테마 편집기. 핵심 흐름이
  아니고 유지 비용이 크다.
- 사용자가 만드는 패널 (Herdr 의 mod). 격리 경계와 패널 API 의 설계가 크다. 구체적인 필요가 생기면 다시 본다.
- Electron 을 네이티브 GUI 로 바꾸기, 터미널 중심의 대화 모델, SSH 로 다른 기계에 데몬 설치하기. 이유는
  [Herdr 조사](../competitive/herdr/README.md)에 있다.
- 브라우저 요소 고르기 (Orca 의 Grab). 브라우저 패널이 먼저 안정되어야 한다. 필요하면 R9 에서 다시 본다.

## 5. 결정 (제안)

- **U-1 글자 크기:** 대화 본문, 코드, 보조 글자의 기본값을 올린다 (예: 대화 14→15px, 코드 12→13px). 크기 조절은
  앱 전체 확대(Z1)로 한다. 글꼴 설정 분리(Z4)는 설정 화면(S1)이 생긴 뒤에 한다. 대화 영역은 지금부터 별도
  토큰(`--text-reading`)을 쓴다. 그래서 나중에 Z4 가 토큰 하나만 바꾼다.
- **U-2 이동 기록의 범위:** 보기(새 스레드, 스레드, 현황판, 원격 호스트)와 열린 스레드만 기록한다. 오른쪽 패널을
  열고 닫는 것은 기록하지 않는다. 기록은 창마다 따로 둔다. 지워진 스레드는 건너뛴다.
- **U-3 확대 값 (2026-11-25 바뀜, #2626):** 영역마다 값을 둔다. 창의 페이지 배율은 100% 이다. renderer 가 본문
  보기(home, fleet, thread, remote), 사이드바, 위 막대, 오른쪽 패널의 탭마다, 터미널, dot 옆 칸, dot 창, ChatGPT
  옆 칸에 CSS `zoom` 을 따로 건다. 터미널은 배율을 글자 크기에 곱한다. 브라우저 패널의 웹 페이지는 `browser-page`
  값을 쓴다. ⌘+ / ⌘− / ⌘0 은 포커스한 영역을, ⌘ + 휠은 포인터 아래 영역을 바꾼다. 사이드바와 위 막대는 설정
  창에서만 바꾼다. 옛 단일 값은 본문 보기로만 한 번 옮긴다. 아래는 바뀌기 전의 결정이다: 앱 전체에 하나의 값을 둔다. 본 창과 dot 창이 같은 값을 쓴다. main 이 `userData` 에 저장한다.
- **U-4 판정의 위치:** 주의와 순서를 정하는 항목(§3.5 뒤의 문단)은 plan 23 을 따른다. 스레드 이름 바꾸기,
  보관, 되감기, 갈래는 공식 app-server 요청이고 Gateway 를 거친다.

- **U-5 명령 표의 위치:** 명령 표는 `desktop/src/shared/` 에 1 개를 둔다. main 의 앱 메뉴와 renderer 의 팔레트,
  단축키 창, 오른쪽 클릭 메뉴가 같은 표를 읽는다. 표는 ID, 제목, 검색어, 단축키만 가진다. 실행 코드는 각 쪽에 둔다.
- **U-6 안내 창의 패널 단계:** 패널은 한 번에 1 개만 열린다 (`uiStore` 의 `panel`). 그래서 스위치 대신 미리
  보기로 한다: 카드를 누르면 창 뒤에서 그 패널이 열린다. 패널 모델은 바꾸지 않는다. 안내를 끝냈는지는 앱 설정
  (`shared/settings.ts`)에 저장한다.

## 7. 검증

- 화면 시험은 가짜 Gateway 와 숨긴 창으로 한다 (`npm run e2e`). 모델을 부르는 요청을 보내지 않는다 (D-13).
- U1 의 시험: 확대 단계와 저장, 확대 뒤 브라우저 패널 위치, 이동 기록(뒤로, 앞으로, 지워진 스레드 건너뛰기),
  입력창의 편집 메뉴, ↑ 키 프롬프트 불러오기, ⌘F 찾기.
- 확대 뒤에 대화 목록(가상 스크롤)의 높이 측정, 맨 아래 따라가기, 터미널 열과 행 맞추기를 확인한다.
- `blueprint/` 도 같은 토큰을 읽는다. 토큰을 바꾸면 블루프린트 화면도 확인한다.

## 8. 근거 공백

- 네 앱 모두 실행하지 않았다. 화면에서 동작을 확인하지 않았다.
- Herdr 항목은 설치 파일의 정적 문자열과 스크린샷 1 장에서 읽었다. 소스 저장소는 읽지 않았다.
- Codex 앱의 Dock 배지, 사이드바 오른쪽 클릭 메뉴 전체, 코드 블록 복사 버튼은 공식 문서에 없다.
- OmO 전용 항목은 설치 파일의 정적 문자열에서 읽었다. 실제로 보이는지와 언제 보이는지는 확인하지 않았다.
- OmO 가 확대 값을 재시작 뒤에도 유지하는지는 확인하지 못했다.
