## 한 줄 요약

지금의 블로그 기능은 사용자가 단계마다 값을 넣는 공동 편집기다. 이 계획은 그것을 "작업을 고르면 Akra 가 글 파일을
만든다"로 바꾼다. 글쓰기 규칙은 스킬에 두고, 실행과 저장은 커널 확장(플러그인)이 맡는다.

## 1. 사용자가 원하는 것 (요청 2026-11-23)

- 플러그인처럼 붙는 자동 블로그 작성 기능이다. 구성은 스킬 + 플러그인이다.
- 사용자가 마감 단계와 모델을 직접 입력하지 않는다.
- 결과물이 무엇인지 바로 보인다.

## 2. 현재 구현 (PR `841c62bf`, 2026-11-23)

`akra.tech-blog` 확장은 명령 9개(`configure`, `create`, `open`, `list`, `save`, `figure`, `accept`, `write`, `review`)를
가진다. 화면은 `desktop/src/renderer/extensions/TechBlogPanel.tsx`, 처리는 `scripts/tech_blog_studio.py` 다.

글 1개를 끝내려면 사용자가 아래 순서를 모두 한다.

1. 설정에서 확장을 켠다.
2. 글 주제, 글의 구성, 조사 방식, 근거 파일 경로를 넣는다.
3. 모델 ID 를 글자로 넣는다.
4. "AI에 초안 요청"을 누른다. 끝나면 "제안을 원고에 적용"을 누른다.
5. 공개용 PNG 와 설명을 등록하고, Markdown 참조를 원고에 직접 붙인다.
6. 모델 ID 를 다시 확인하고 "독립 검수"를 누른다.
7. 검수 결과가 "수정 요청"이면 4번부터 다시 한다.

## 4. 목표 동작

1. 사용자가 패널에서 최근 작업(커밋 범위 또는 머지된 PR)을 고른다. 고르지 않으면 지난 글 뒤의 작업이 대상이다.
2. "글 만들기"를 한 번 누른다.
3. Akra 가 근거 수집, 초안, 검수, 고쳐 쓰기를 차례로 한다. 화면은 지금 단계를 보여준다.
4. 끝나면 화면에 글 미리보기, 파일 경로, 검수 요약이 나온다. 결과물은 Markdown 파일 1개와 그림 폴더다.
5. 사용자는 파일을 열거나, 한 줄 요청으로 다시 만들게 하거나, 원고를 직접 고친다.

사용자가 넣는 값은 0개가 기본이다. 주제와 고쳐 쓰기 요청은 선택이다.

## 5. 구조: 스킬 + 플러그인

| 부분 | 맡는 일 | 위치 |
| --- | --- | --- |
| 스킬 | 글의 구성, 문체, 근거 규칙, 금지 사항. 사람이 읽고 고친다. | `assets/app-server/skills/akra-tech-blog/SKILL.md` (신규). `akra-issue-draft-review` 와 같은 방식이다. |
| 플러그인 (커널 확장) | 대상 선택, 근거 수집, 모델 실행, 검수 반복, 파일 저장, 작업 상태. | 기존 `akra.tech-blog` 확장. 버전 2. |
| Desktop 패널 | 대상 고르기, 진행 표시, 결과 보기. 판단을 하지 않는다. | `TechBlogPanel.tsx` |

### 5.1 모델

- 사용자가 모델을 넣지 않는다. 워커는 `--model` 을 주지 않고 Codex 의 기본 모델을 쓴다.
- 검수는 같은 모델의 새 세션으로 한다. 지금도 `codex exec --ephemeral` 이므로 세션은 독립이다.
- 모델을 바꾸는 설정은 이 계획에 넣지 않는다. 필요가 확인되면 "설정 → 확장"에 값 1개를 추가한다.

### 5.2 근거

- 대상은 커밋 범위다. 근거는 그 범위의 커밋 메시지와 diff 다. 모두 SHA 에 고정한다.
- 크기 한도를 넘으면 큰 파일의 diff 부터 요약 줄(`--stat`)로 바꾼다. 한도 값은 B1 에서 정한다.
- 주장마다 근거 ID 를 붙이는 현재 계약과 지문(`input_sha256`) 검사는 그대로 쓴다.

### 5.3 검수와 마감

- 초안 뒤에 검수를 자동으로 한다. 결과가 `revise` 이면 사유를 넣어 다시 쓴다. 최대 2회다.
- 2회 뒤에도 `revise` 가 남으면 글을 버리지 않는다. 파일을 만들고, 남은 지적을 결과 화면과 파일 머리말에 적는다.
- 그림은 선택이다. 그림이 없는 글도 완료할 수 있다. 등록한 그림이 있으면 현재 검사를 그대로 적용한다.

### 5.4 결과물

- 글마다 폴더 1개: `<출력 폴더>/<날짜>-<slug>/post.md`, 그림은 같은 폴더의 `assets/` 다.
- `post.md` 머리말(front matter): 제목, 날짜, 기준 커밋 범위, 검수 상태.
- 기본 출력 폴더는 Akra 런타임 폴더다. 저장소의 추적 파일을 바꾸지 않는다. 다른 위치는 §8 Q2 에서 정한다.
- 외부 발행(GitHub, 블로그 플랫폼)은 이 계획 밖이다.

### 5.5 지우는 것

- 화면: 모델 ID 입력, 글의 구성, 조사 방식, 근거 파일 경로, "제안을 원고에 적용", "독립 검수" 버튼.
- 명령: `write`, `accept`, `review` 를 `generate` 1개로 합친다. `save`, `open`, `list`, `figure`, `configure` 는 남긴다.
- 글의 구성과 조사 방식은 스킬이 대상의 내용으로 정한다.
- `scripts/tech_blog.py` 의 독립 실행(`discover`, `packet`, `check`, `review`)은 바꾸지 않는다.

## 6. 조각

조각 1개가 PR 1개다. 순서대로 한다.

| 조각 | 범위 | 완료 기준 |
| --- | --- | --- |
| B1 | `generate` 명령, diff 근거, 자동 검수 반복, `post.md` 저장, 패널 단순화 | 가짜 모델로 "글 만들기" 1회에 `post.md` 가 생긴다. 모델 ID 입력란이 없다. 그림 없는 글이 완료된다. 검수 2회 실패 사례에서 파일과 남은 지적이 함께 나온다. 커널 재시작으로 끊긴 작업은 "중단"으로 보이고 다시 요청할 수 있다. |
| B2 | 글쓰기 규칙을 `SKILL.md` 로 옮김 | Python 의 프롬프트 문자열이 없다. 스킬 본문이 워커 입력에 들어가는 것을 시험이 확인한다. |
| B3 | 자동 제안: 작업이 머지되면 "이 작업으로 글을 만들까요?"를 plan 20 의 제안으로 보낸다 | 가짜 Gateway 에서 제안이 뜨고, 수락하면 B1 의 `generate` 가 시작된다. 거절하면 같은 범위를 다시 묻지 않는다. |
| B4 | 대화에서 부르기: 스킬이 커널 명령으로 `generate` 를 요청한다 | 조사 뒤에 범위를 정한다. `hub-skills/akra-kernel` 의 명령 경로를 쓸 수 있는지 먼저 확인한다. |

검증은 모델 턴 없이 한다. `tech_blog.py` 의 `MODEL_COMMAND` 대체 경로와 가짜 Gateway 를 쓴다.

## 7. 위험

- `--ignore-user-config` 때문에 워커는 사용자의 Codex 설정을 읽지 않는다. 기본 모델과 접속 경로가 일반 대화와 다를 수 있다. B1 에서 실제 환경 1회로 확인한다. 이 확인은 모델 턴을 쓰므로 사용자 허락이 필요하다.
- diff 근거는 파일 발췌보다 크다. 한도가 없으면 토큰 사용량이 는다.
- 공개 저장소다. 자동 글에 내부 이름이나 비밀 값이 들어갈 수 있다. 결과물은 로컬 파일이고, 발행은 사람이 한다.
- 기존 `tech-blog.sqlite3` 의 글은 버전 2 에서도 열려야 한다. B1 에서 읽기 호환을 시험한다.
