# Akra 커널 확장 구조와 저장 공간 분석기

**설계 제안 · 2026-11-21 · Windows 첫 버전**

구현은 [상위 이슈 #2596](https://github.com/RefinedStone/codex-exec-loop/issues/2596)에서 추적한다. 폴더 점유율 표는 [Desktop 이슈 #2620](https://github.com/RefinedStone/codex-exec-loop/issues/2620), 사용자와 AI의 공동 탐색은 [이슈 #2630](https://github.com/RefinedStone/codex-exec-loop/issues/2630)에서 추적한다.

Akra 커널 계층에 확장을 등록한다. 커널이 확장의 활성 상태와 실행 권한을 소유한다. Desktop은 사용자가 확장을 켜고 끄고 결과를 볼 수 있는 클라이언트다. 첫 플러그인은 사용자가 고른 드라이브의 공간을 분석한다. 큰 폴더를 찾으면 그 안에서 공간이 한두 곳에 집중되는지 확인한다. 공간이 작은 항목에 흩어져 있으면 그 부모 폴더를 결과로 남긴다. 사용자는 같은 화면에서 그 판단의 근거와 실제 파일을 확인한다.

[TreeSize Free 열 정의](https://manuals.jam-software.com/treesize_free/EN/available_columns.html) · [보기 옵션](https://manuals.jam-software.com/treesize_free/EN/view.html)

Akra는 이 계층 표를 기본 보기로 채택한다. 막대는 같은 부모의 형제들을 비교할 때 읽는다. 예를 들어 12 GiB짜리 worktree 안의 9 GiB 캐시는 75%다. 더 큰 폴더의 20%가 이 캐시보다 클 수 있으므로 막대 옆에 항상 절대 용량을 둔다. 전역 순위는 §4의 ‘큰 폴더 요약’에서 확인한다.

## 3. 커널이 확장을 소유하고 Desktop이 조작한다

기능 패키지는 한 벌이다. 작성자는 확장 ID, 호환 API 버전, 실행 범위, 명령·조회·이벤트 스키마, 필요한 권한을 선언한다. Rust 처리기가 기능을 구현한다. 전용 화면이 필요하면 같은 ID에 대응하는 Desktop 패널을 함께 제공한다. CLI나 TUI는 지원하는 명령과 결과를 자기 방식으로 표현할 수 있다.

현재 커널의 `akra/kernel/describe`는 프로토콜 명세를 제공한다. 현재 명령 포트와 Gateway의 attach 경로는 저장소를 기준으로 한다. 아래의 확장 카탈로그, 활성 상태 관리, 저장소를 열기 전의 로컬 사용자 연결은 **신규 설계**다. [명세](https://github.com/RefinedStone/codex-exec-loop/blob/449bc985e1e93a7236fb52ab98f03cb2d2bec065/src/adapter/inbound/kernel_protocol/spec.rs) · [명령 포트](https://github.com/RefinedStone/codex-exec-loop/blob/449bc985e1e93a7236fb52ab98f03cb2d2bec065/src/application/port/inbound/kernel_command_port.rs) · [Gateway 연결](https://github.com/RefinedStone/codex-exec-loop/blob/449bc985e1e93a7236fb52ab98f03cb2d2bec065/src/adapter/inbound/gateway/kernel.rs)

| 커널 확장 호스트 | 카탈로그, 호환성 검사, 범위별 활성 설정, 호출 권한, 작업 상태와 이벤트. 특정 플러그인의 구현은 조립 시점에 연결한다. |

### 확장의 적용 범위

- **저장소 범위.** 특정 저장소의 상태를 다루는 확장은 그 저장소 커널이 설정과 작업을 소유한다. A에서 끄면 B는 설정을 유지한다.
- **로컬 사용자 범위.** 드라이브 분석기는 같은 PC의 같은 OS 사용자에게 한 인스턴스를 둔다. Gateway에서 저장소 선택 전에 해당 범위에 연결하는 경로를 추가한다. 작업을 만드는 권한과 활성 설정은 이 호스트 한 곳에 둔다. 동일 사용자·볼륨·분석 옵션의 동시 요청은 같은 작업 ID를 돌려준다. 원격 호스트나 다른 사용자의 볼륨·결과와 섞이지 않는다.
- 두 범위는 같은 확장 계약을 쓴다. 첫 버전은 빌드에 포함한 신뢰된 확장을 등록한다. 외부 패키지 설치는 별도 실행 격리와 패키지 검증이 필요한 후속 범위다.

### 켜기, 실행하기, 끄기

1. Desktop의 ‘설정 → 확장’이 커널에 목록을 요청한다. 커널은 설치 버전, 호환 여부, 활성 상태와 적용 범위를 반환한다. 이 관리 경로는 개별 확장을 꺼도 사용할 수 있다.
2. 사용자가 저장 공간 확장을 켠다. 커널이 권한과 호환성을 확인하고 활성 설정을 저장한다. 상태 변경 이벤트를 받은 Desktop이 패널을 표시한다. 이 시점에 디스크 I/O를 시작하지 않는다.
3. 사용자가 드라이브를 선택한 뒤 ‘분석’을 누른다. 커널이 대상 볼륨과 권한을 확인하고 작업 ID를 반환한다. 패널 닫기와 Desktop 종료는 해당 클라이언트의 구독을 해제한다. 실행 호스트가 살아 있으면 같은 사용자로 다시 연결해 진행 상태를 읽을 수 있다.
4. 사용자가 확장을 끈다. 커널이 먼저 새 호출을 차단한다. 진행 중인 읽기 전용 스캔에 취소를 요청하고 ‘끄는 중’을 알린다. 작업을 정리하면 ‘꺼짐’을 알린다. CLI를 포함한 모든 진입점에 같은 정책을 적용한다. 일반 확장에서 이미 시작한 쓰기 작업은 확장이 선언한 안전 중단 지점까지 진행한다.
5. 같은 요청을 재시도해도 작업을 중복 생성하지 않는다. Desktop 재연결 시 커널의 상태를 다시 읽는다. 권한 부족이나 버전 충돌이 발생하면 관리 화면에 커널이 반환한 사유를 표시한다. 호스트 재시작 후에는 저장한 활성 설정을 복원하고 이전 분석이 중단되었음을 알린다.

### 새 플러그인을 붙이는 비용

새 확장은 패키지와 조립 지점에만 추가한다. 공통 커널의 명령 분기와 Desktop 셸의 패널 분기를 기능마다 수정할 필요가 없도록 한다. 확장 호출은 이름공간과 버전으로 식별하고 등록된 입력·출력 스키마를 검사한다. 기존 내장 명령의 고정 타입 계약을 유지한다. 화면 패널은 별도로 지연 로딩할 수 있다.

## 4. 드라이브를 분석하는 방법

**한 번 순회하면서 여러 깊이의 결과를 만든다.** 일반 디렉터리 열거에서 루트의 이름 목록만 읽어서는 어느 폴더가 가장 큰지 확정할 수 없다. 먼저 큰 폴더의 정확한 값을 구하고 다시 그 내부 전체를 읽으면 같은 비용을 두 번 낸다.

1. 사용자가 로컬 볼륨을 고른다. 첫 선택값은 C 드라이브다. 루트 직속 폴더와 파일을 즉시 보여준다. 아직 방문하지 않은 폴더의 크기는 ‘대기’다.
2. 루트의 각 가지에 순회 기회를 준다. 폴더를 읽을 때 발견한 하위 폴더를 공용 작업 큐에 넣는다. 루트에 큰 폴더 하나만 있어도 그 아래에서 병렬화할 수 있다. SSD 4개, HDD 또는 장치 종류 미확인 시 1개를 초기 비교값으로 잡는다. 우선순위는 사용자가 펼친 가지, 관측량이 큰 가지에 준다. 오래 대기한 가지도 차례를 얻는다.
3. 파일의 메타데이터를 읽어 직속 폴더에 기록한다. 자식의 집계가 끝나면 부모에 병합한다. 화면에는 ‘현재까지 확인한 용량’과 읽은 파일 수를 보여준다. 접근 불가와 읽는 중 사라진 항목은 사유별로 센다. 진행 중 순위는 잠정값이다.
4. 완료된 결과에서 아래 규칙으로 펼칠 폴더와 멈출 폴더를 정한다. 화면을 펼칠 때는 이미 만든 색인을 조회한다. 임계값을 바꿔도 디스크를 다시 읽지 않는다.
5. 폴더별 합계와 부모 ID를 보관한다. 파일명, 직속 부모 ID, 크기, 수정 시각은 작업 전용 로컬 색인에 페이지 단위로 기록한다. 수백만 파일 전체를 renderer 메모리에 올리지 않는다. 색인 자체는 순회에서 제외한다. 실행 호스트는 작업 보존 기간이 끝나거나 사용자가 확장을 끄면 임시 색인을 정리한다. 다시 분석할 때는 새 시각을 표시한다.

### 어느 폴더에서 멈추는가

첫 제안값은 다음과 같다. 확인된 할당 용량을 기준으로 각 **직접 자식 폴더**에 적용한다.

- 자식이 **1 GiB 이상**이면 펼친다. 드라이브에서 차지하는 비율이 작아도 여러 GiB짜리 빌드 캐시를 찾을 수 있다.
- 또는 자식이 **256 MiB 이상**이고 **부모의 20% 이상**이면 펼친다. 상대적으로 작은 프로젝트에서도 집중된 경로를 따라갈 수 있다.
- 어느 자식도 위 두 기준 중 하나에 해당하지 않으면 **현재 부모가 최종 폴더**다. 자식 여럿이 기준을 넘으면 각각 같은 규칙을 적용한다. 드라이브 루트는 항상 한 단계 펼치고 루트 직속 파일도 보여준다.
- 일부 자식만 펼치면 나머지 자식과 직속 파일을 **‘이 폴더의 나머지’**로 묶는다. 요약 순위는 최종 폴더와 나머지 묶음만 합산한다. 부모 총량은 탐색용으로 표시한다. 두 값을 더하지 않는다.
- 스캔이 불완전한 가지에는 ‘일부 확인’과 사유를 붙인다. 최종 순위를 확정하지 않는다. 자동 펼침 기준 아래에 있는 경로도 사용자가 직접 열어볼 수 있다.

| 측정 예시 | 큰 폴더 요약에서 내려간 결과 |
| --- | --- |
| `cache` 1 GiB. 16개 자식이 각각 64 MiB | `cache` 1 GiB에서 멈춘다. ‘가장 큰 하위 폴더 64 MiB’가 근거다. |
| `build` 1 GiB. `obj` 768 MiB. 나머지는 직속 파일 256 MiB | `obj`를 펼친다. 부모의 나머지 256 MiB를 별도 표시한다. |
| `dev` 100 GiB. 여러 형제 중 한 worktree가 3 GiB | 3% 비중이어도 해당 worktree를 펼친다. 여러 형제가 크면 모두 순위에 들어간다. |
| `downloads` 8 GiB. 직속 이미지 파일 하나가 7.8 GiB | 최종 폴더는 `downloads`다. 상세 화면 첫 파일이 7.8 GiB를 설명한다. |

### Windows에서 용량을 읽는 기준

기본 순위는 **확인된 디스크 할당 용량**이다. 파일의 논리 크기는 옆에 표시한다. 할당량을 확인할 수 없는 파일은 별도 개수와 논리 크기로 표시한다. 압축 파일, sparse 파일, 클라우드 자리표시자는 두 값이 크게 다를 수 있다. 파일 본문을 열거나 클라우드 파일을 다운로드하지 않는다. [Microsoft 파일 크기 필드](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_standard_info)

하드링크는 볼륨과 파일 ID로 묶는다. 같은 폴더 계층에서 발견한 여러 경로는 상세 목록에 모두 표시한다. 합계에는 한 번만 포함한다. 두 형제에 걸친 링크의 할당량은 공통 조상의 ‘공유 파일’ 항목에 둔다. 합산 결과가 병렬 탐색 순서에 따라 달라지지 않는다. 링크 식별이 불완전하면 해당 범위의 합계에 표시한다. 경로 하나가 사라질 때 확보될 용량은 별도 정보다. [Microsoft 하드링크와 정션](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions)

정션과 디렉터리 심볼릭 링크의 대상은 따라가지 않는다. 볼륨 경계를 넘어가거나 순환하는 일을 방지한다. 알 수 없는 재분석 지점은 건너뛴 사유를 표시한다. OS가 보고하는 볼륨 사용량, 확인한 파일 할당량, 남은 차이를 각각 보여준다. 접근 제한과 파일 시스템 메타데이터 등 여러 원인이 차이에 포함될 수 있다. [Microsoft 재분석 지점](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-points)

## 5. 사용자가 보게 될 화면

최초 1회 **설정 → 확장 → 저장 공간 분석기**에서 이 사용자 범위의 확장을 켠다. 이후 진입 경로는 **도구 → 저장 공간 → 이 PC의 드라이브 선택 → 분석**이다. 상단에는 선택한 볼륨, 진행 상태, 취소를 둔다. 기본 보기는 펼칠 수 있는 **폴더 점유율 표**다. 첫 단계는 드라이브 직속 항목이다. 각 단계의 형제를 할당량 내림차순으로 정렬한다. 펼치면 부모 행을 유지한 채 바로 아래에 자식이 나타난다. 상단에서 **큰 폴더 요약**으로 전환하면 §4의 최종 폴더와 나머지 묶음을 볼 수 있다. 두 보기는 같은 색인과 선택 항목을 사용한다.

| 이름 | 할당량 | 부모 대비 점유율 | 상태 |
| --- | ---: | ---: | --- |
| 예시 worktree | 12 GiB | — (보기의 루트) | 완료 |
| ↳ target | 9 GiB | 75.0% | 완료 |
| ↳ assets | 2 GiB | 16.7% | 완료 |
| ↳ 직속 파일 합계 | 1 GiB | 8.3% | 완료 |

기본 열은 이름, 할당량, 부모 대비 점유율, 집계 상태다. 논리 크기, 파일·폴더 수, 수정 시각은 추가로 표시한다. 분모는 같은 스냅숏에서 측정한 직속 부모의 할당 바이트다. 숫자와 막대에 같은 값을 사용한다. 루트 또는 분모가 0이거나 미확인이면 비율을 비워 두고 사유를 표시한다. 일부만 읽었으면 양쪽에서 확인한 바이트의 비율에 ‘잠정’을 붙인다. 분모와 확정 여부는 행 상세에서도 확인할 수 있다. 부모의 직속 파일·공유 파일 묶음은 §4의 귀속 규칙에 따라 한 번만 센다. 다른 보기에서 합산한 순위나 페이지에 표시된 행만으로 분모를 다시 계산하지 않는다.

좌우 화살표로 가지를 펼치고 접는다. 위아래 화살표로 표시된 행을 이동한다. 보조 기술이 행의 이름·깊이·펼침 상태·용량·점유율을 읽을 수 있게 한다. 선택 항목의 트리맵은 켜고 끌 수 있는 보조 보기다. 사각형의 면적은 할당량을 나타낸다. 표와 트리맵에서 같은 노드를 가리키며 모든 탐색은 표만으로도 가능하다. [W3C Treegrid 키보드 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/treegrid/)

행을 선택하면 **직속 파일**, **하위 폴더**, **정리 판단 근거**를 보여준다. 파일 목록은 이름과 확장자로 필터링하고 크기로 정렬할 수 있다. 큰 파일이 깊이 묻혀 있을 때는 ‘하위 파일 포함’으로 범위를 바꾼다. 탐색기에서 열 때는 사용자가 선택한 결과 경로를 호스트가 확인한다.

### Worktree와 개발 잔여물

1. 용량 분석 중 `.git` 디렉터리나 파일을 만나면 저장소 후보로 기록한다. 알려진 Akra 저장소도 조회한다. Git 공통 디렉터리별로 `git worktree list --porcelain -z`를 한 번 호출한다. 등록 경로와 실제 경로를 대조한다. 이 과정을 거쳐 서브모듈과 linked worktree를 구분한다. [Git worktree](https://git-scm.com/docs/git-worktree)
2. Worktree 행에는 저장소, 브랜치 또는 detached HEAD, 전체 점유량과 그 안의 큰 경로를 표시한다. 예를 들어 ‘worktree 12 GiB, 그중 target 10 GiB’로 보여준다. 보호된 worktree에서도 빌드 산출물이 얼마나 큰지 확인할 수 있다.
3. 기본 체크아웃, Git 잠금, 진행 중인 세션, Akra 런타임 슬롯은 보호 사유를 표시한다. 수정 파일, 추적되지 않은 파일, 로컬에만 있는 커밋, 확인할 수 없는 소유 상태는 ‘검토 필요’다. 외부 도구가 만든 worktree의 활성 여부를 확인할 수 없으면 그대로 표시한다. 오래된 시각이나 clean 상태만으로 폐기 가능하다고 판정하지 않는다.
4. Git의 `prunable`은 등록 정보의 상태를 뜻한다. 경로가 이미 없으면 확보할 로컬 폴더 용량은 없다. 이름이 `target`, `node_modules`, `Library`인 폴더에는 경로와 프로젝트 표식을 대조해 유형을 붙인다. 사용자가 분류 근거를 볼 수 있게 한다.
5. 첫 버전은 분석, 상세 확인, 탐색기 열기까지 제공한다. 향후 정리 기능은 작업 직전의 경로·변경·사용 상태를 다시 확인한다. worktree의 소유 도구를 통해 명시한 대상만 정리한다. 기존 저장소 정리 스크립트는 옵션에 따라 브랜치와 원격 참조도 처리한다. 범용 폴더 정리 동작에서 이 스크립트를 호출하면 사용자 선택보다 범위가 넓어진다. [기존 정리 스크립트](https://github.com/RefinedStone/codex-exec-loop/blob/6eb7104410dd2476241a44b29ffda6285b387da5/scripts/cleanup_merged_worktrees.sh)

### 사용자와 AI가 같은 결과를 탐색하는 방법

**사용자 → AI.** 사용자가 worktree 행에서 ‘이 폴더를 AI에 묻기’를 선택한다. 보낼 범위와 대화를 확인하고 질문을 보낸다. Desktop은 커널이 발급한 공유 참조를 대화에 첨부한다. 참조는 사용자·호스트·대화·스캔·스냅숏·선택한 하위 트리에 묶인다. 공유 루트 아래의 이름과 메타데이터, 해당 폴더의 worktree 보호 사유만 제공한다. 공유 루트의 상위 경로와 부모 비율은 숨긴다. 일상적인 클릭과 키보드 이동은 화면 선택만 갱신한다.

**AI → 사용자.** “이 worktree의 어디가 큰가요?”라는 질문에 모델은 공유 범위 안의 자식을 조회한다. 답변 예시는 “target이 9 GiB로, 이 worktree 12 GiB의 75%입니다”이다. 답 옆의 ‘표에서 보기’는 같은 스냅숏의 해당 행을 가리킨다. 사용자가 누르면 조상을 펼치고 행에 초점을 맞춘다. 제안을 닫거나 다른 대화로 이동하면 현재 화면 선택은 유지한다. 재스캔 후 예전 참조가 만료되면 그 사실과 다시 공유할 경로를 안내한다. 같은 이름의 새 폴더로 자동 이동하지 않는다. 이 흐름은 Akra의 기존 제안·응답 설계를 따른다. [관찰과 제안 계획](20-akra-observe-and-offer.md)

**커널 조회 계약.** Desktop, CLI, 모델 도구는 같은 집계 서비스를 사용한다. 모델은 기본적으로 상위 10개와 다음 커서를 읽는다. 제안하는 v1 호출은 다음과 같다.

| 조회 | 입력 | 반환 |
| --- | --- | --- |
| `get_node` | 공유 참조, 노드 ID | 현재 노드, 상태, 보호 사유, 근거 참조 |
| `list_children` | 공유 참조, 부모 ID, 정렬, 커서, 페이지 크기 | 확인한 직속 항목, 전체 항목 수 또는 미확인, 다음 커서 |
| `find_hotspots` | 공유 참조, 기준값, 페이지 크기, 커서 | §4와 같은 최종 폴더·잔여량, 멈춘 근거, 다음 커서 |

각 결과는 스키마 버전, 스냅숏 ID, 노드 ID, 허용된 범위의 부모 ID·상대 이름, 할당·논리 바이트, 비율의 분자·분모, 완료 여부와 누락 사유를 담는다. 바이트는 손실 없는 십진 정수 문자열로 전송한다. 정렬의 동률은 스냅숏 안의 노드 ID로 해소한다. 커서는 스냅숏·범위·정렬·필터에 묶고 페이지 크기는 최대 100으로 제한한다. 진행 중 데이터는 공유 시점의 리비전에 고정한다. 새 집계는 명시적으로 갱신한다. 모델 답변이 인용하는 ID와 화면이 이동하는 ID는 같다.

**접근 경계.** 커널이 호출마다 현재 확장 활성 상태, 대화와 사용자의 공유 범위, 만료 여부를 검사한다. 임의의 절대 경로를 받지 않는다. 범위를 벗어난 ID와 존재하지 않는 ID에는 외부 경로의 존재를 알려주지 않는 동일한 오류를 반환한다. 파일명은 구조화한 데이터로 취급한다. 파일 본문 읽기·삭제·이동은 이 분석 도구의 작업 목록에 넣지 않는다. 공유 해제와 확장 비활성화는 후속 조회를 중단한다. 이미 전송한 대화 내용은 소급 취소할 수 없으므로 보내기 전에 공유 범위를 표시한다.

**연결 방식.** 기존 `akra describe --json`과 커널의 명령·조회 명세를 출발점으로 삼는다. 첫 구현은 같은 스키마로 CLI JSON 조회와 대화 도구 어댑터를 제공한다. MCP를 쓰는 클라이언트는 같은 계약을 `inputSchema`, `outputSchema`, `structuredContent`에 매핑할 수 있다. Akra 전용 MCP 서버 배포는 이 계획의 선행 조건에 넣지 않는다. [커널 명령 명세 계획](18-k4-command-spec.md) · [MCP 도구 명세](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

## 6. 개발 순서와 합격 기준

| 순서 | 구현 범위 | 합격 기준 |
| --- | --- | --- |
| 1 | 커널 확장 등록과 상태 계약, Desktop 관리 화면을 추가한다. | 화면 없는 예제 확장을 켜고 끌 수 있다. 재시작 후 설정이 복원된다. 꺼진 명령은 Desktop과 CLI 양쪽에서 거절된다. 잘못된 패키지가 다른 확장을 막지 않는다. |
| 2 | 저장 공간 플러그인과 일반 권한 스캐너를 연결한다. | 저장소를 열기 전에도 스캔한다. 두 창이 동일 볼륨·옵션으로 요청하면 작업 하나를 공유한다. 확장을 끄면 양쪽에 반영된다. 위 네 가지 예시의 최종 폴더와 잔여 바이트가 일치한다. 하드링크는 한 번만 센다. 정션은 순환하지 않는다. 접근 거부와 중단을 완료로 표시하지 않는다. |
| 3 | Git 등록 정보와 Akra의 사용 상태를 결합한다. | 활성 · 잠금 · 변경 · detached · 슬롯 · 상태 미확인 사례를 구분한다. 같은 worktree의 합계와 내부 캐시를 이중 합산하지 않는다. |

추가 인수 시나리오는 12/9/2/1 GiB 예시를 화면과 모델 테스트 도구가 함께 읽는 경우다. 두 경로의 노드 ID·분자·분모가 일치해야 한다. 사용자가 근거 링크를 누르면 75.0% 행이 선택되어야 한다. 다른 대화, 공유 범위 이탈, 취소된 공유, 만료 스냅숏 요청은 차단한다. 0바이트·부분 집계·동률 페이지, 키보드만 사용하는 탐색도 검증한다. 모델 응답은 고정된 도구 호출로 재현하며 실제 모델 턴은 검증의 전제 조건에 넣지 않는다.

첫 실험의 목표값은 분석 시작 후 1초 안에 진행 상태를 보이고, 취소 입력 후 1초 안에 새 디렉터리 배정을 멈추는 것이다. 이미 Windows에 제출한 I/O가 끝날 때까지는 ‘취소 중’을 표시한다. 스캔 중 패널 닫기·재열기, 디스크 분리, 작업 프로세스 종료도 검증한다. 병렬 수와 자동 펼침 임계값은 제안값이다. 실제 드라이브 측정과 사용자 결과 검토 후 기본값을 확정한다.

조사에는 TreeSize Free 설치본 화면과 내장 도움말, 공식 제품·표준 문서, 오픈소스 프로젝트 설명, Akra 소스를 사용했다. 이 문서의 용량 사례는 설명용 데이터다. 실제 PC의 드라이브 분석과 성능 측정은 구현 후 검증 항목이다.
