# 05. 위험과 미결 질문

상태: Proposed · 기준일: 2026-11-05

## 1. 위험

| ID | 위험 | 영향 | 대응 |
| --- | --- | --- | --- |
| K-01 | app-server 프로토콜이 자주 바뀐다 (0.166 은 alpha, 거의 매주 갱신) | 앱 타입과 실제 메시지가 어긋난다 | Gateway 는 그대로 전달하므로 영향이 작다. `generate-ts` 를 다시 실행하고 버전 경고를 둔다 (04 §9) |
| K-02 | Akra 의 일부 테스트가 불안정하다 (실행마다 다른 테스트 실패) | 회귀를 구분하기 어렵다 | P1~P3 은 기준선과 비교한다. R5 전에 원인을 정리한다 (Q-07) |
| K-03 | Akra 의 아키텍처 규칙이 엄격하다 | Gateway 구조가 커질 수 있다 | P1 첫 작업에서 가장 작은 구조를 정하고 확인받는다 |
| K-04 | CLI 계정이 free 플랜이다 | 실측과 실사용이 한도에 걸린다 | D-13 을 따른다. 녹화 파일을 재생해서 시험한다 |
| K-05 | 범위가 계속 넓어진다 | 완성하지 못한다 | MVP 범위(D-12)를 지킨다. 실제 불편 하나에 기능 하나를 대응한다 |
| K-06 | Electron 보안 설정 실수 | renderer 에서 로컬 파일과 프로세스에 접근된다 | 04 §8 의 설정을 고정하고 시험으로 확인한다 (P2 완료 기준 5) |
| K-07 | 공개 저장소에 민감 정보가 들어간다 | 자격 증명, 회사 정보, 대화 내용이 노출된다 | 녹화 파일과 회사 정보를 커밋하지 않는다. 리뷰에서 확인한다 |
| K-08 | 기존 TUI 와 Gateway 가 각자 app-server 를 실행한다 (P-08) | 같은 `~/.codex` 를 두 프로세스가 쓴다 | 공식 Codex 앱과 CLI 도 같은 홈을 함께 쓴다. 문제가 보이면 R5 에서 합친다 |
| K-09 | unix 소켓 경로 한도 (macOS 104바이트) | Gateway 나 app-server 가 시작하지 않는다 | 시작할 때 길이를 검사하고 오류를 명확히 출력한다 |
| K-10 | macOS 와 Windows 의 IPC, 권한, 종료 신호가 다르다 (D-15) | OS 별 코드와 시험이 늘어난다 | 차이를 Listener, 권한 처리, 수명 관리에 가둔다. Session 코드는 같은 스트림 타입을 쓴다. 두 OS 모두 검증한다 (Windows: `scripts/check_native_pr.ps1`) |

## 2. 미결 질문

| ID | 질문 | 결정 시점 | 기본안 | 상태 |
| --- | --- | --- | --- | --- |
| Q-01 | 하네스 기능 중 무엇을 언제 연결하는가 | R5 전 | P3 이후 사용자의 불편 목록으로 정한다 | 열림 |
| Q-02 | 자체 compact 를 어느 수준부터 하는가 | R6 전 | 수준 1 (설정)부터 | 열림 |
| Q-03 | 두 접속이 같은 승인 요청에 거의 동시에 답하면 어떻게 되는가 | P1 실측 | 먼저 도착한 답이 쓰인다고 가정한다. 두 번째 답의 오류는 무시한다 | 실측 필요 |
| Q-04 | codex 버전을 어떻게 관리하는가 | P2 전 | PATH 의 설치본을 쓴다 (2026-11-05: macOS Homebrew 0.149.1, Windows npm 0.159.0). 업그레이드는 04 §9 절차로 한다 | 열림 |
| Q-05 | Gateway 데몬을 어떻게 시작하는가 | R8 전 | MVP 동안은 앱이 시작한다. 이후 LaunchAgent 로 바꾼다 | 열림 |
| Q-06 | Windows, Linux 를 지원하는가 | R8 전 | macOS 와 Windows 를 지원한다 (D-15). Linux 는 미정 | Windows 결정 (2026-11-05), Linux 열림 |
| Q-07 | 불안정 테스트를 언제 정리하는가 | R5 전 | P1~P3 은 기준선 비교, R5 전에 정리 | 열림 |
| Q-08 | 앱 이름과 아이콘 | R8 전 | 가칭 "Akra Desktop" | 열림 |
| Q-09 | 구독 접속이 모두 끊긴 스레드의 진행 중인 턴이 계속되는가 | P1 실측 | 계속되지 않으면 Gateway 가 자체 접속으로 구독을 유지한다 | 실측 필요 |
| Q-10 | 저장소를 모노레포로 하는가 (D-04) | P1 전 | Akra 저장소 안 `desktop/` | 결정 (2026-11-05, D-04 승인) |
| Q-11 | 열린 브랜치 2개(`codex/akra-config-layers`, `fix/thread-start-model`)를 어떻게 하는가 | P1 전 | 사용자에게 확인한다 | 확인 필요 |

질문이 결정되면 이 표의 상태를 고치고, 결정 내용은 [03](03-decisions.md) 에 새 항목으로 추가한다.
