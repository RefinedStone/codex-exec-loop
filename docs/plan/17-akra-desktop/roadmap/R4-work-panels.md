# R4. 업무 패널 (GitHub, Jira, Slack)

상태: 진행 중 (GitHub 완료, Jira·Slack 남음) · 기준일: 2026-11-06 · 선행: P3 · 규모: 패널당 약 1주

## 목표

업무 도구의 핵심 정보를 앱 안에서 보고, 필요한 내용을 에이전트 작업으로 바로 넘긴다.

## 범위 (패널별)

| 패널 | 보여 줄 것 | 에이전트로 넘기기 |
| --- | --- | --- |
| GitHub | 내 PR, 리뷰 요청, PR 상태와 CI | PR 리뷰 코멘트로 수정 스레드 시작 |
| Jira | 내 티켓, 상태, 설명 | 티켓 내용으로 새 스레드 시작 |
| Slack | 멘션, DM, 지정 채널의 새 메시지 | 스레드 내용을 프롬프트로 보내기 |

한 번에 하나씩 만든다. 사용자가 P3 이후 남긴 불편 목록의 순서를 따른다.

## 설계 메모

- 패널은 main 의 서비스가 외부 API 를 호출한다. renderer 는 메시지 버스로 요청한다.
- **회사 계정 분리 (D-14):**
  - 회사 계정의 자격 증명은 OS 키체인(Electron `safeStorage`)에만 저장한다.
  - 저장소, Akra 설정 파일, 로그, 녹화 파일에 넣지 않는다.
  - 회사의 데이터 정책을 확인한다. 회사 데이터를 개인 Codex 계정으로 보낼 때 특히 확인한다.
- 각 서비스의 공식 API 를 쓴다. 공식 CLI(`gh` 등)가 있으면 그것을 먼저 고려한다.
- "에이전트로 넘기기"는 새 스레드의 첫 메시지를 미리 채우는 방식으로 시작한다. 자동 실행은 하지 않는다.

## 미결

- Slack 은 조직 정책상 사용자 토큰 발급이 가능한지 확인한다.
- 알림(새 멘션 등)을 데스크톱 알림으로 보낼지 정한다.

## 진행 기록

### 2026-11-06: GitHub 패널 (PR 1)

- 데이터: main 이 공식 CLI `gh` 로 GraphQL 한 번을 호출한다 (`desktop/src/main/githubService.ts`). 내 열린 PR
  (마지막 커밋의 CI 상태, 해결되지 않은 리뷰 스레드 수)과 나에게 온 리뷰 요청이다. 자격 증명은 gh 가 OS 키체인에
  둔다. 앱은 토큰을 읽거나 저장하지 않는다 (D-14). gh 는 셸 없이, 홈 폴더에서, 대화형 질문 없이 실행한다.
- 화면: 상단 "GitHub" 버튼으로 오른쪽 패널을 연다 (브라우저 패널과 같은 자리, 한 번에 하나). 열 때와 "새로 고침"
  때만 읽는다. 제목을 누르면 github.com 주소만 기본 브라우저로 연다.
- 에이전트로 넘기기: 해결되지 않은 리뷰가 있는 내 PR 에 "스레드로 넘기기" 버튼이 있다. 리뷰 코멘트(파일, 줄,
  작성자, 본문)로 첫 메시지를 만들고, 열린 스레드의 폴더(없으면 폴더 선택)에서 새 스레드를 열어 입력창만 채운다.
  보내기는 사용자가 한다. 코멘트는 2,000자, 메시지는 20,000자에서 자른다.
- 확인 (실제 gh, 읽기만, 창 숨김): 내 PR 17개와 리뷰 요청을 3.4s 에 읽었다. 해결되지 않은 리뷰가 있는 PR 2개의
  메시지 항목 수가 리뷰 수와 같았다. 넘기기로 빈 새 스레드가 열리고 입력창이 채워졌다 (턴 없음, 보내지 않음).
  턴이 없는 새 스레드는 기록에 남지 않았다.
- Jira, Slack: 회사 토큰 발급과 데이터 정책 확인(D-14)이 먼저 필요해서 아직 하지 않았다.
