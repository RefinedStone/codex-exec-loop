# R6. 자체 compact

상태: 수준 2 수동 제어 구현 (#2776) · 기준일: 2026-11-26 · 선행: P3, A06 입력 예약

## 목표

긴 대화의 문맥을 줄이는 시점(compact)을 사용자가 고른다. D-05(A+)를 지킨다. 원본 대화와 이번 수준 2의
압축 내용은 Codex가 관리하고, Akra는 요청 시점과 관측 상태를 다룬다. 직접 만든 요약본과 정책의 소유권은
수준 3을 선택할 때 별도로 설계한다.

## 수준 (Q-02 로 선택)

| 수준 | 방법 | 개입 정도 |
| --- | --- | --- |
| 1 | 설정 `compact_prompt` (요약 지시문), `model_auto_compact_token_limit` (시작 기준) | 요약 방식과 시점을 바꾼다 |
| 2 | Gateway 가 원하는 시점에 `thread/compact/start` 를 보낸다 | 시점을 제어한다 |
| 3 | Akra 가 `thread/items/list` 로 기록을 읽고 직접 요약한다. 요약을 `developerInstructions` 에 넣어 새 스레드를 시작하거나 `thread/fork` 를 쓴다 | 요약 내용을 완전히 제어한다 |
| 4 | 매 턴 문맥을 직접 구성한다 | app-server 로는 할 수 없다. 엔진을 다시 만들어야 하므로 하지 않는다 |

## 설계 메모

- 이번 범위는 **수준 2**이다. 사용자가 현재 대화에서 명시적으로 누른 수동 압축만 제공한다.
  `thread/compact/start`는 renderer의 기존 JsonRpcClient에서 Gateway의 공식 app-server 전달 경로를 쓴다.
  `src/adapter/inbound/gateway/router.rs`의 `ClientTextRoute::Forward`와 `session.rs`의 upstream 전달이
  실제 경계이다. 별도 `akra/*` interceptor나 자체 요약 엔진을 추가하지 않는다.
- 수준 3 에서는 "이 스레드는 저 스레드를 요약해서 이어 간다"는 연결 정보를 Akra 가 저장한다. 앱은 이
  연결을 따라 기록을 이어서 보여 준다.
- 요약에는 모델 호출이 필요하다. 실험할 때 D-13 의 허락 규칙을 따른다.
- 근거: [codex-app-server.md](../reference/codex-app-server.md) §6

## 수동 압축의 상태 계약

- 접속 중이며 기록이 로드된 쓰기 가능한 현재 대화에서만 시작한다. 진행 중인 턴, 새 입력 접수,
  예약 전송, 결과 불명인 예약, 다른 압축이 있으면 거절한다. 압축이 진행 중이거나 결과 불명이면
  같은 대화의 일반 입력/steer와 예약 dispatch도 막는다. A06의 공통 입력 경계를 재사용한다.
- `thread/compact/start { threadId }`의 빈 응답은 접수만 뜻한다. 같은 접속과 대화의 새 턴에서
  `contextCompaction` 항목 완료와 `turn/completed` 성공을 함께 관측해야 완료이다.
  항목이 끝났어도 최종 턴이 실패/중단이면 실패로 표시한다. 구형 `thread/compacted` 알림은
  이미 관측한 같은 턴에 한해서만 항목 완료 근거로 쓴다.
- `-32601`은 미지원, 다른 JSON-RPC 거절은 실패이다. 응답 대기 30초, 완료 대기 180초 초과와
  연결 손실은 **결과 불명**이다. 모델 요청은 자동으로 반복하지 않는다.
- 결과 불명에서 **상태 다시 확인**은 `thread/turns/list`의 최신 20개 턴만 조회한다.
  이미 관측한 턴 ID 또는 요청 전 마지막 턴 뒤의 유일한 새 압축 턴을 찾았을 때만 회복한다.
  기존 `thread/resume`/페이지 읽기로 현재 대화 화면을 다시 읽고 같은 세대·대화의 압축 결과를
  확인한 뒤 입력 차단을 해제한다. 조회와 화면 재조회는 각각 30초 제한이다. 조회 중 다른 대화로
  이동하면 화면을 돌리지 않는다. 기준 턀이 누락되거나 후보가 여러 개, 재조회 실패, 관측 범위 밖이면
  결과 불명을 유지한다. 자동 성공·자동 재압축은 없다.
- 상태는 현재 앱 창의 메모리에만 보관한다. 자체 요약, fork 계보, 자동 임계값 변경은 이번 범위에 없다.

## 검증

`desktop/test/threadCompaction.test.ts`는 공식 응답/알림을 합성해 접수·완료·오류·미지원,
프레임 전 active 알림, 중복/지연 알림, 시간 초과, 연결 손실과 읽기 복구를 시험한다.
`desktop/test/e2e/thread-compaction.mjs`는 실제 Electron과 가짜 Gateway에서 화면 및 공통 입력 차단을
확인한다. 개발 중 실제 모델을 호출하지 않는다. 설치된 엔진과 계정의 실제 압축 성공은 검증 범위가 아니다.
