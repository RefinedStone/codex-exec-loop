# 01. 배경과 목표

상태: Proposed · 기준일: 2026-11-05

## 1. 사용자 상황

- 사용자는 회사에서 백엔드 개발을 한다. 하루 업무에서 다음 도구를 오간다.
  - 코딩 에이전트: 회사가 지원하는 Claude Code, 개인 Codex
  - GitHub (PR, 리뷰), Jira (티켓), Slack (대화)
  - 브라우저: 사내 QA 환경에서 기능을 직접 시험
- 도구마다 앱이 달라서 전환 비용이 크다.
- 사용자는 공식 Codex 데스크톱 앱을 많이 썼다. 이 앱의 대화 경험(프로젝트별 스레드, 스트리밍,
  승인, worktree)을 기준으로 삼는다.
- 사용자는 Akra 의 소유자이다. Akra 는 `codex app-server` 위의 Rust 클라이언트이다. 계획 큐,
  worktree 슬롯, 검증, PR 전달 같은 외부 루프(L4)를 가진다. 현재 화면은 터미널 TUI 이다.

## 2. 목표

1. 앱 하나에서 코딩 에이전트 대화와 업무 도구를 처리한다.
2. 공식 엔진을 그대로 써서 공식 Codex 앱과 같은 응답 품질을 유지한다.
3. 기능을 하나씩 추가해서 효율을 점진적으로 올린다. 실제로 불편했던 일 하나에 기능 하나를
   대응한다.
4. 코드 전체를 사용자가 소유한다.

## 3. 비목표

| 항목 | 이유 | 다시 볼 시점 |
| --- | --- | --- |
| Claude 연결 | 앱 완성 후 확장한다 (D-02) | [R7](roadmap/R7-claude-backend.md) |
| 클라우드 에이전트(OpenAI dots) 연결 | 비공개 백엔드이다 (D-03) | 하지 않음 |
| 자체 엔진(L2) 구현 | 공식 엔진 품질 유지가 목표이다 | 하지 않음 |
| 공식 Codex 앱 UI 복제 | 비공개 코드이다. 구조만 참고한다 | 하지 않음 |
| 여러 사람에게 배포 | 개인 도구이다 | [R8](roadmap/R8-packaging-and-operations.md) 이후 |
| 사용량 절약 기능 | 지금은 필요 없다 (D-07) | 필요할 때 |
| Linux 데스크톱 | 사용자 환경이 macOS 와 Windows 이다 | 미정 (Q-06) |

## 4. 제약

- **공식 인터페이스 우선:** Codex 엔진은 `codex app-server` 로만 연결한다.
- **Codex 사용량 최소화:** 개발과 검증에서 턴을 만들지 않는다. 턴이 필요하면 사용자 허락을
  받는다 (D-13).
- **계정 분리:** Akra 저장소는 RefinedStone 신원으로 작업한다. 회사 계정과 회사 데이터를 섞지
  않는다 (D-14).
- **사용량 한도:** 현재 CLI 의 Codex 로그인 계정은 free 플랜이다 (2026-11-05 확인).
- **공개 저장소:** 이 문서와 코드는 공개된다.
- **지원 OS:** macOS 와 Windows 를 함께 지원한다 (D-15). OS 마다 다른 부분은 IPC, 권한, 종료 신호,
  데몬 시작 방식이다.
- **Akra 저장소 규칙:** 아키텍처 경계 테스트, worktree 절차, PR 절차를 따른다
  ([06 인계 가이드](06-handoff-guide.md)).

## 5. 성공 기준 (MVP)

사용자가 하루 동안 Codex 대화 업무를 공식 Codex 앱 대신 Akra Desktop 으로 처리할 수 있으면 MVP 가
성공이다. 세부 기준은 다음과 같다.

1. 프로젝트 목록과 프로젝트별 스레드 목록을 본다.
2. 새 스레드를 시작한다. 기존 스레드를 재개한다.
3. 응답이 끊김 없이 스트리밍된다.
4. 명령 실행과 파일 변경의 승인 요청에 답한다.
5. 진행 중인 턴을 중단하거나 방향을 바꾼다 (steer).
6. 앱을 닫아도 진행 중인 턴은 데몬 쪽에서 계속된다. 앱을 다시 열면 이어서 본다. (Q-09 실측으로 확인)

## 6. 검토 경과

이 계획에 이르기까지 검토한 순서이다. 자세한 근거는 [`reference/`](reference/) 에 있다.

1. Akra 를 업무 하네스로 고쳐 쓰는 안을 먼저 검토했다. 범위가 커져서 보류했다.
2. 공식 Codex 데스크톱 앱의 구조를 관찰했다. "Electron UI + 공개 app-server 엔진" 구조임을
   확인했다 ([codex-desktop-app.md](reference/codex-desktop-app.md)).
3. Claude 데스크톱 앱, OmO, Orca 의 코드 공개 여부를 확인했다. 데스크톱 UI 를 공개한 것은 Orca
   (MIT) 뿐이다 ([alternatives.md](reference/alternatives.md)).
4. Orca 플러그인 경로를 검토했다. 가장 빠르지만 소유권과 구조 통제가 약하다.
5. Electron 과 Tauri 를 비교했다. 앱 안 브라우저(Chromium) 요구 때문에 Electron 을 골랐다.
6. Akra + Electron 으로 정했다 (D-01). 이후 설계 쟁점을 하나씩 결정했다: 기준 데이터(D-05),
   데몬(D-06), 전송(D-09), 작업공간(D-10), 프로토콜(D-11), MVP 범위(D-12).
7. 사전 검증(P0)에서 Akra 빌드, 현재 Codex 와의 호환성, app-server 다중 접속을 확인했다.
