# 승인 공유본의 인계 계약 (#2701)

상위 #2414. 제안 정책: 프로젝트 범위에서 Akra가 게시한 이슈를 인계할 때 최근 확정한 공유본의 해시와 원격 필드 해시가 같아야 한다. 불일치·미확정 게시·일지 조회 실패는 오류이며 새 승인·게시 후 다시 시도할 수 있다. 로컬 재연결은 원문 열람 승인일 뿐 AI 인계를 새로 승인하지 않는다.

## 경계

- 작업 폴더를 지정한 수동 인계: 대표 checkout으로 scope를 해석하고 게시 lease 아래에서 실제 안정 이슈 ID에 해당하는 일지를 검사한다. 게시 이력이 없는 이슈는 현재 공개본을 현재 AI 공개 정책으로 가린다. 중복 순서, 미확정 전송, 전송 결과를 모르는 abandon은 보류한다. 과거 일지의 승인 정책/템플릿 판은 게시할 때 확인되며 자동 실행 권한으로 해석하지 않는다.
- 작업 폴더가 없는 수동 인계는 기존 비프로젝트 공개본 읽기다. 이 범위에서는 프로젝트의 승인 여부를 주장하지 않고 현재 사용자 AI 정책만 사용한다. 프로젝트에 종속된 실행 권한은 부여하지 않는다.
- 자동 실행의 승인과 정책 버전 검증은 별도의 기존 실행 허가 계약을 변경하지 않는다. 인계 결과는 프롬프트 초안이지 자동 실행 허가가 아니다.
- 모든 인계는 원격 공유본을 다시 AI 공개 정책으로 가린다. Vault 원문이나 댓글은 반환하지 않는다.

## 검증

Gateway 통합 회귀에서 같은 승인 판 인계와 외부 편집 후 거절, 재연결 후에도 승인 공유본 불일치 시 거절을 확인한다. 테스트는 합성 원격 및 키를 사용한다. 실제 사용자 모델/이슈는 사용하지 않는다.
