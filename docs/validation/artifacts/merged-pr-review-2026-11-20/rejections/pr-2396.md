### 반려 근거

현재 stale 결과는 generation/transcript/Ready 검증에서 버리지만 staged 파일 소유권 토큰을 전달하지 않아 파일 정리는 미구현 상태다. 경로만으로 삭제하는 방식은 사용자 원본을 지울 수 있다. staging 생성·참조·폐기 소유권과 동일 스레드 submit 뒤 probe 허용 정책을 함께 정하는 별도 계약으로 두고 이번 변경에 추가하지 않는다.

### 재검토 조건 — 추후 제안

owned staging handle과 공유 첨부 수명 규약을 도입한 뒤 stale/completion/drop 모두에서 자신이 만든 파일만 정리하는 회귀로 구현.
