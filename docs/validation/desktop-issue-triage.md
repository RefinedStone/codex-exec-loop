# Desktop 판정·관찰 보고·정책 보기 검증 (#2542)

## 화면과 조회

이슈 패널은 목록, 관찰 보고, 정책 보기로 나뉜다. 목록 제목을 선택하면 그 이슈의 상세를 열며, 원격 이슈 링크는 별도 버튼으로 유지한다. 일반 폭에서는 목록과 상세를 오가고, 최대화하면 상세의 본문과 판정을 함께 넓게 볼 수 있다.

기존 저장된 수집 모드와 동기화 명령을 유지한다. 새 상세와 정책 기능은 읽기 전용이며 작업 생성, 모델 호출, 승인 또는 정책 변경을 보내지 않는다. 결정 카드와 실행 개입은 이 범위에 포함하지 않는다.

| 조회 | 소유하는 값 |
| --- | --- |
| issue_automation | 수집 상태와 catalog revision |
| issues | 현재 페이지, 서버 그룹과 전체 관찰 보고 |
| issue | 전체 안정 좌표 한 건의 현재 공유본, 판정, 관문과 같은 snapshot의 보고 |
| issue_automation_policy | 대표 workspace의 효과 정책, 합성 출처와 정책 파일 위치 |

정책 조회는 host와 command-only 입구 모두 같은 application 계약을 사용한다. 파일이 없으면 내장 기본값을 표시하고, 읽기 실패나 잘못된 정책이면 policy_blocked를 표시한다. 잘못된 파일의 값 대신 기본값을 보여 주지 않는다.

## 현재 내용과 늦은 응답

선택은 provider, server, repository, issue, 대표 workspace의 전체 안정 좌표를 사용한다. 선택 변경 즉시 이전 상세를 비운다. 응답의 좌표나 연결·관심 영역·작업 폴더 세대가 달라지면 늦은 성공, 오류와 완료 처리를 받지 않는다.

catalog revision이 바뀌면 이전 상세를 숨기고 다시 읽는다. 뒤처진 응답을 무한 재조회하지 않으며 한 번 재시도한 뒤에도 갱신되지 않으면 오류를 표시한다. 더 최신 상세가 오면 이전 목록은 무효화한다. 보고의 revision도 응답 snapshot과 일치해야 한다.

본문은 현재 관찰이 Shared일 때만 표시한다. Unknown, Withheld, legacy에서는 과거 공유본을 가져오지 않는다. 현재 Shared 응답의 판정만 stale이면 현재 본문은 표시하고 판정 갱신 필요를 알린다. 연결부의 상세 무효화와 판정 자체의 stale을 구분한다.

## 서버 판정과 보고

renderer는 서버의 groups와 item_indices 순서를 따른다. 판정의 eligibility, readiness, risk_class, effective_mode는 표시만 하고, 이유의 summary와 next_summary 및 관문의 action·enabled·순서를 그대로 사용한다. enabled는 실행 허가를 새로 만드는 의미가 아니다.

관찰 보고는 현재 추적하는 전체 저장소 연결의 장부 snapshot이다. 현재 페이지나 최근 30일로 집계하지 않는다. binding ID, 전체 수, 자동 시작·사람 승인·제외 등 서버 집계를 직접 표시한다. 관찰의 가정 수준은 실제 활성 관문과 구분한다.

## 효과 정책과 출처

출처는 최종값을 비교해 추정하지 않는다. 정책을 합성할 때 명시된 필드와 실제 연산 입력에서 기록한다. 같은 값을 명시한 경우와 빈 목록도 출처를 유지한다.

일반 override, 최소 상한, AND, 교집합, 합집합, mode cap을 각각 표현한다. 복합 제한에는 실제 참여한 출처를 함께 표시한다. 정책 판은 기존 정규화된 효과값의 SHA-256을 유지하며 출처·파일 위치·workspace는 판에 넣지 않는다.

파일 adapter는 경로를 결정한 뒤 그 파일을 한 번 읽은 snapshot으로 위치·내용·읽기 상태를 묶는다. 화면은 정책 원문이나 I/O 오류 원문을 받지 않는다. 차단 시 파일 범위·필드·이유·다음 행동과 확인 가능한 위치를 보여 준다.

## 정책 파일 열기

열기 요청은 정책 응답의 대표 workspace, 파일 scope, 표시된 경로와 로컬 host 의도를 전달한다. attach 요청이 하위 폴더여도 대표 workspace를 사용한다.

main은 알려진 두 파일 위치를 독립적으로 계산해 표시된 경로와 대조한다. 사용자 파일은 AKRA_HOME 또는 사용자 홈의 .akra 아래 issue-automation.toml이고, 저장소 파일은 대표 workspace의 .akra/issue-automation.toml이다. 원격 host 의도, 임의 경로, 상대 경로 및 안전하지 않은 링크 대상은 거부한다. 점 경로(. 또는 ..), Windows의 끝 공백·마침표, POSIX의 역슬래시처럼 정규화나 편집기 URL 변환 중 다른 대상으로 바뀔 수 있는 비정규 경로도 명시적으로 거부한다. 정책 조회에서 그런 경로를 읽을 수 있어도 열기 동작은 다른 위치로 바꾸어 열지 않는다.

VS Code 처리기가 있으면 파일 주소로 열고, 없거나 열기가 실패하면 파일 또는 존재하는 부모 위치를 표시한다. 파일 연결로 실행하는 shell.openPath는 사용하지 않는다. 조회와 열기 경로는 파일을 만들거나 권한을 바꾸지 않는다. 비동기 오류는 정책 화면에서 확인할 수 있다.

## 검증

연결 회귀는 전체 좌표 불일치, 선택 A→B 응답 역전, 새 revision, 재시도 상한, 독립 오류, 관심 영역 변경, workspace 변경, 재접속을 확인한다. 정책 회귀는 기존 효과값·해시 보존, 같은 값과 빈 목록 출처, 복합 제한, 파일 snapshot과 원문 비공개를 확인한다.

숨김 Electron 시험은 가짜 Gateway와 임시 앱 데이터를 사용한다. 모델 턴이나 조향 요청을 보내지 않는다. 정책 파일 열기의 UI 시험은 IPC를 기록용 stub으로 바꾸며 실제 OS 호출은 하지 않는다. main의 경로 및 편집기 fallback은 주입된 OS 경계로 별도 검증한다.

실행 결과: Windows Full gate, Rust 정책·조회·wire·schema·아키텍처 회귀, Desktop 타입 검사와 Vitest 810개 통과(7개 기존 skip), 전체 숨김 Electron E2E가 통과했다. 파일 열기 회귀 69개는 실제 임시 파일·링크 불변성과 주입된 OS 경계를 포함한다. 추가 Linux 검사와 게시 head의 CI 결과는 PR에서 추적한다.
