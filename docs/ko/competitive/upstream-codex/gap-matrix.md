# 업스트림 Codex와 Akra의 격차 매트릭스

[English](../../../competitive/upstream-codex/gap-matrix.md)

이 문서는 [OpenAI Codex v0.144.1 감사](analysis.md)를 Akra의 결정 사항으로 전환한다. 변경 불가능한
소스, 릴리스 바이너리 프로브, 원시 샘플, Akra 기준선 링크와 한계는
[evidence.md](evidence.md)에 있다. `Ahead`는 고정된 스냅샷에서 명시된 경계에 대한 근거가 더 강하다는
뜻이지, 제품이나 보안에 대한 총점이 아니다.

업스트림 Codex는 의존성이자 참조 클라이언트다. 따라서 이 매트릭스는 다음을 구분한다.

- **프로젝션(project)**: Akra 애플리케이션 경계를 통해 공식 런타임의 의미를 보존한다.
- **도입(adopt)**: 권한을 중복하지 않고 upstream 패턴을 사용한다.
- **거부(reject)**: upstream이 소유한 동작을 위한 Akra 하위 시스템을 추가하지 않는다.
- **차별화(differentiate)**: 수락된 의도, 격리, 검증, 리뷰, 통합과
  운영자 사실에 투자한다.
- **관찰(observe)**: Akra가 내부적으로 해결할 수 있는 것처럼 가장하지 않고 upstream 위험을 추적한다.

## 즉각적인 결론

P0-A 터미널 사실은 `prerelease`의 `5a9d342f`에 존재한다. 현재 라이브 경로는 일치하는
`turn/completed` 알림을 일반적인 성공으로 축소하지 않고 타입이 지정된 완료, 실패, 중단, 알 수 없는
결과를 보존한다. P0-B 적용된 엔벨로프 프로젝션은 `7960ecca`에 있고, P0-C1 닫힌 항목 ID는
`7514eb05`에 있다. 이 원자적 슬라이스는 P0-C2 제한된 점진적 활동을 구현한다.
P0-D1의 제한된 점진적 활동 레일은 `b53559ca`에, P0-D2의 일시적으로 유지되는 Diff/Output 인스펙터는
`594859a6`에, P0-D3의 타입이 지정된 우선순위 레일은 `89264f6e`에 있다. 이제 P0-D4에는 결정론적 보충 E3
캡처와 소스 빌드 후보 `0a5f06ea`에 연결된, 리뷰를 마친
[E1-E4 물리적 크기 조정 아티팩트](../../../validation/artifacts/pr-1926-physical-resize/README.md)가
모두 있다. E1-E4 세트는 공유 터미널 프리미티브에 대한 수동 리뷰어 의무를 충족한다.
모든 캡처는 `supplemental-unmatched`로 유지되고, `terminal-baseline`에 포함되지 않으며, 릴리스된
Akra 런타임 활동 근거가 아니다. P0-D는 그 릴리스된 Akra 런타임 활동 캡처가 없기 때문에만 부분 상태로
남아 있다.
내구성 있는 복구, 검증/전달 프로젝션과 더 넓은 표면 렌더링은 P0-A부터 P0-D3까지의 암묵적인 결과가
아니라 별도의 소유자로 남는다.

## 도입

### 타입이 지정된 의미론적 경계

outbound 경계에서 공식 app-server 어휘를 사용한 다음, 운영상 의미를 보존하는 작은 애플리케이션 타입으로
축소한다. 프로젝션은 닫혀 있어야 한다. 알려진 모든 wire 변형은 타입이 지정된 사실이나 명시적으로
무시/수정된 결정에 매핑되고, 알 수 없는 모든 변형은 프로토콜 드리프트로 표시된다. 메서드 이름만으로
분류하는 것으로는 충분하지 않다.

### 요청된 상태, 적용된 상태, 관찰된 상태

모든 실행 뷰는 다음을 구분해야 한다.

```text
requested by Akra/operator
-> accepted response from app-server
-> effective thread/turn envelope
-> later reroute/settings/status observation
```

유효 상태에는 모델/제공자, 추론 노력 수준, 서비스 티어, cwd, 샌드박스, 승인
정책/리뷰어, 협상된 경우 권한 프로필, 관련 환경 분류가 포함된다. 안정 경로에서는
사용자 지정 구성 기본값이 적용될 수 있지만 명명된 프로필 출처는 사용하지 못할 수 있다.
레거시 샌드박스 프로젝션의 이름을 해당 사용자 지정 프로필로 바꾸면 안 된다. 요청된 필드는 upstream이
이를 적용했다는 증거가 아니다.

### 제한된 클라이언트 의미론

제한된 큐, 지연/과부하 마커, 종료 기한, 상관관계 ID, 부정 기능 테스트를 도입한다. Akra가 소유한
어댑터와 애플리케이션 서비스는 upstream이 백프레셔를 제공한 뒤 제한 없는 큐를 추가해서는 안 된다.
델타가 많은 스트림에는 터미널, 승인, 항목 경계, 전달 관련 사실을 절대 버리지 않는 병합 또는 제한된
손실 정책이 필요하다.

### 공식 세션 출처

안정된 공식 목록/읽기/재개/포크 의미론을 사용하고 계보, 소스, cwd, Git, 에이전트,
이력, 아카이브, 임시 상태, 커서 사실을 보존한다. 이러한 사실을 Akra 계획 및 전달 ID에 연결하되,
그 링크를 두 번째 세션 권한으로 만들지 않는다.

### 런타임 호환성 근거

해석된 Codex 바이너리, app-server 버전, 스키마/핸드셰이크, 샌드박스 헬퍼, 인증 상태,
유효한 실행 정책을 설치 호환성 영수증으로 취급한다. 공식 단순 tar의 Bubblewrap 실패는 버전 출력만으로
준비 상태를 입증할 수 없음을 증명한다. Akra 아카이브에는 Codex가 포함되지 않으므로, 대응책은 테스트된
전제 조건과 진단이지 Akra 번들에 `bwrap`를 벤더링하는 것이 아니다.

## 거부

### 런타임 중복

제공자 클라이언트, 모델 실행, 도구 레지스트리, shell/patch/fs 엔진, MCP 호스팅,
압축, 롤아웃 영속성 또는 의미론적 메모리를 추가하지 않는다. Upstream이 이를 소유하며 빠르게 변경된다.

### 원시 app-server 노출

일반 JSON-RPC, 파일시스템, 셸, 명령, 프로세스, 플러그인, 구성 또는 자격 증명
메서드를 Admin, Telegram, webhook 또는 원격 노드 API를 통해 전달하지 않는다. 인증은 인증된
app-server 클라이언트의 로컬 사용자 권한을 축소하지 않는다. 공개 DTO는 허용 목록에 남고 애플리케이션
서비스에 매핑된다.

### 실험적 연속성 주장

app-server daemon, WebSocket, remote-control, realtime, 원격 환경 또는
실험적 이력 페이징을 지원되는 Akra 연속성 계약으로 홍보하지 않는다. 제한된 UDS 실험은 기존 복구
설계에 정보를 제공할 수 있지만, 먼저 연결 해제, 업데이터 재시작, 구성 재생과 플랫폼 지원을 재현해야 한다.

### 전달 상태로서의 런타임 상태

다음 중 어떤 것도 Akra 완료와 동일시하지 않는다.

- 상태를 검사하지 않은 `turn/completed`;
- 항목 완료 또는 최종 어시스턴트 메시지;
- Codex 계획 완료, 목표 완료, 리뷰 모드 또는 하위 에이전트 완료;
- 테스트, 리뷰, commit, PR 또는 merge를 주장하는 작업자 설명;
- 아카이브된 공식 스레드;
- 권위 있는 항목/턴 결과가 없는 `serverRequest/resolved`.

### 자동 메모리 확장

공식 세션 출처와 수락된 계획 링크가 불완전한 동안에는 Akra 임베딩이나 추출된 개인 메모리를 추가하지
않는다. 실험적 upstream 메모리 경로는 그러한 하위 시스템이 만드는 개인정보 보호, 비용, 속도 제한,
수정, 정정과 샌드박스 의무를 보여 준다.

## 차별화

### 런타임 범위보다 런타임 사실 우선

Akra는 일반적인 클라이언트보다 더 정밀해야 한다.

- retrying, running, completed, interrupted, failed, recovery-pending, unknown은 서로 구분된다.
- 항목 시작, 진행, 완료와 권위 있는 턴 결과는 계속 상호 연관된다.
- 요청된 실행 구성과 유효한 실행 구성은 계속 표시된다.
- 알 수 없는 wire 값은 조용한 성공이 아니라 검사 가능한 드리프트로 남는다.
- 원시 추론/도구 출력에는 명시적인 보존, 수정, 크기 정책이 적용된다.
- 모든 inbound 표면은 하나의 애플리케이션 프로젝션을 사용한다.

### 리뷰된 운영 계층

기본 Akra 생명주기는 다음과 같이 유지된다.

```text
accepted intent
-> isolated lane and lease
-> official runtime activity
-> candidate report
-> commit and frozen source
-> local validation clear or not-required
-> publication and PR
-> trusted CI clear or not-required
-> frozen-head review/check gate
-> rebase/integration and remote verification
-> PR/source/slot cleanup
```

명시적인 자율 우회 경로는 정책 출처를 유지하며 리뷰된 전달인 것처럼 가장하지 않는다.
공식 턴 성공은 이 생명주기 초반의 입력 하나일 뿐이다.

### 교차 표면 플릿 운영

TUI는 기본 대화형 표면이고, Admin은 운영 플릿 표면이며, CLI,
Telegram과 자동화는 제한된 명령/뷰다. 이들은 터미널 사실, 현재 항목,
유효 엔벨로프, 승인 소유권, 레인/임대, 검증, 리뷰, 통합, 복구 상태를 공유해야 한다.
게임 디오라마는 영속화된 의미론적 전환만 애니메이션으로 표현할 수 있다.

## 릴리스 불변 조건 수정 사항

### 골든 프로토콜 충실도

기존 Canvas
[골든 프로토콜 충실도 추적](../agent-canvas/gap-matrix.md#golden-프로토콜-충실도-trace)을
비교 실험에서 출하되는 app-server 어댑터의 Akra 릴리스 불변 조건으로 승격한다.

**계약 변경 사항**

- 지원되는 정확한 Codex CLI/app-server 버전을 고정하고 해석된 바이너리 다이제스트를 기록한다.
- 정규화된 안정 및 실험적 스키마 아티팩트를 별도로 생성하고 보존한다.
- 일반 Akra 경로를 `experimentalApi: false`로 초기화하고, 명시적인 옵트인 제품 결정 없이 애플리케이션
  계약이 실험적 메서드나 필드에 의존하면 테스트를 실패시킨다.
- 안정/실험적 요청 및 알림 수를 방향 파악 용도로만 인벤토리화한다.
- 각 행이 기능 단계, 소유자 슬라이스, 소스 픽스처,
  활성 싱크와 `planned` 또는 `required` 게이트 상태를 선언하는 버전이 지정된 매니페스트를 유지한다.
- 현재 출하되는 경로의 행만 게이트한다. 미래 표면은 `planned`로 남아 녹색으로 집계될 수 없고,
  그 표면을 소유한 기능 PR이 캡처를 제공하고 행을 `required`로 승격한다.
- P0-A는 성공, interrupted, failed,
  retrying-then-success, nonretrying-error-with/without-terminal, drifted terminal, terminal
  sink failure에 대해 상호 배타적인 라이브 경로를 승격한다.
- P0-B는 requested/applied/rerouted 엔벨로프 행을 승격하고, P0-C1/C2는 항목 및 델타 행을 승격한다.
  복구, 승인, 병렬, 전달, Admin과 이후 inbound 표면은 구현될 때 자신의
  source-to-sink 행만 승격한다.
- 새로 생성된 메서드/항목/상태, 누락된 예상 캡처, 중복 터미널,
  상관관계 불일치 또는 unknown을 success로 승격하는 경로가 있으면 실패시킨다.
- 정규화된 정의 본문이 일치하더라도 안정 런타임 픽스처와 옵트인 실험 픽스처를 분리하여 유지한다.

**필수 증명**

- 결정론적 가짜 app-server 픽스처 및 source-to-sink 매니페스트;
- 하나의 릴리스 바이너리 안정 핸드셰이크와 부정 실험 기능 요청;
- 정확한 스키마 콘텐츠 해시 및 버전 메타데이터;
- 현재의 잘못된 `error.params.message` 및 일반 터미널 픽스처가 구현 수정 전에는 실패하고 중첩된
  오류/상태 보존이 있을 때만 통과하는 테스트;
- 비어 있거나 오래된 필수 픽스처 디렉터리로 통과할 수 없고 계획된 행을 통과 근거로 취급할 수 없는
  릴리스 게이트.

### 알려진 카나리아 제한 송신 매트릭스

기존 OpenCode
[릴리스 불변 조건](../opencode/gap-matrix.md#알려진-카나리-기반-제한-외부-전송-매트릭스)의 권한이 아니라 내용을 수정한다.

**계약 변경 사항**

- upstream의 기본 `shell_environment_policy.inherit=all`과
  `ignore_default_excludes=true`를 명시적인 부정 대조군으로 취급한다.
- 현재 출하되는 모든 main, resumed, planning, parallel 자식 실행이 Akra의
  기본 프로세스 정리와 `shell_environment_policy.inherit=core` 및 비밀 제외를 적용함을 입증한다.
- recovery, review-response, automation과 이후 자격 증명을 포함하는 경로를 계획된 행으로 선언한다.
  각 소유 기능 PR은 캡처를 추가하고 자신의 행만 required로 승격한다.
- 정확한 권한 상승 `process-env=all` 및 shell-inherit-all 재정의를 별도로 기록하고 기본 녹색 결과를
  절대 상속하지 않는다.
- 주장을 명명된 값으로 제한하면서 API/OAuth/PAT/private-key 형태의 이름, 프록시 URL, 클라우드 자격 증명,
  SSH 에이전트 핸들과 임의의 비패턴 비밀에 대한 카나리아를 추가한다.
- 구성된 프로세스 인자뿐 아니라 적용된 스레드 엔벨로프와 폐기 가능한 명령 환경을 검증한다.
- 폐기 가능한 `$CODEX_HOME/auth.json` 합성 카나리아와 별도의 파일, keyring 및
  임시 upstream 저장소 관찰을 추가한다. 자격 증명 페이로드를 읽거나 영속화하지 않고 `Auto` keyring 성공,
  파일 fallback, 잔여 `auth.json`, 유효 모드를 다룬다. 환경 정리는 읽을 수 있는 파일을 보호하지 않으며
  Codex는 느슨한 기존 모드를 복구하지 않는다.
- direct-read 및 shell-read 경로를 실행하고, 공식 transcript/tool 싱크를 지원됨, 안전하지 않은 관찰 또는
  알 수 없음으로 분류하되 Akra가 권한이 부여된 읽기를 막을 수 있다고 주장하지 않는다.
- login-profile 처리가 명명된 부모 카나리아를 기본 도구 자식에 다시 도입할 수 없음을 입증하고 timeout 및
  프로세스 트리 정리를 기록한다.
- 합성 `0022` 및 `0077` umask에서 롤아웃 부모/파일 모드에 대한 upstream 관찰 행과 픽스처가 실행한
  모든 공식 archive/compression 경로 이후의 모드 보존을 추가한다. 이는 관찰만 입증하며 Akra를 롤아웃
  권한으로 만들 수 없다.
- 공식 `auth.json`, rollout, MCP/plugin 또는 제공자 내부 저장소를 관찰하되 제어를 주장하지 않고,
  비공개 `$CODEX_HOME` 전제 조건을 운영자 런북에 유지한다.
- 원시 app-server 파일시스템/셸/프로세스 메서드를 금지된 공개 DTO 싱크로 유지한다.

**필수 증명**

- 인자 구성 및 릴리스 바이너리 명령 환경 캡처;
- 비밀이나 대화 기록 내용을 절대 캡처하지 않는 제한된 인증 저장소 선택/잔여물/모드 및 롤아웃
  부모/파일/아카이브 모드 관찰;
- 모든 필수 현재 런타임 종류에 대한 정확한 양성 캡처 및 금지된 싱크 행;
- 기존 불변 조건의 TUI/Admin/CLI/Telegram/log/SQLite/Git/GitHub 스캔;
- Akra 셸 정책 재정의를 제거하면 upstream 기본값이 노출되고 매트릭스가 실패함을 보여 주는 부정 테스트.

현재 표면 매니페스트, 스캐너, 양성 캡처와 금지된 싱크 게이트는 전달 순서의 9번 행이다.
이 문서 감사만으로 녹색으로 간주되지 않는다.

### Codex 설치 호환성 영수증

운영자 전제 조건을 공식 complete-package 헬퍼 또는 호환되는 시스템 `bwrap`를 갖춘 Linux Codex 설치로
즉시 좁힌다. 기존 고정 소스 검증 근거 슬라이스가 근거 스키마를 정의한 후 자동화된 네이티브 패키징 smoke
계약을 수정한다. 그때까지 로컬 부정 프로브와 수동 런북 no-op은 감사/운영자 근거이지 녹색 릴리스 영수증이
아니다. Akra는 자신을 패키징하고 Codex와 완료된 로그인을 외부 전제 조건으로 선언한다. 이 결론을 Akra
패키지 관리자로 바꾸거나 upstream `bwrap`를 Akra 아카이브에 추가하지 않는다.

**계약 변경 사항**

- 자격 증명이나 임의의 환경을 로깅하지 않고 정확히 해석된 `codex` 실행 파일, 버전, 다이제스트,
  설치 형태 분류, 샌드박스 헬퍼 출처, 프로브 종료를 식별한다.
- 지원된다고 주장하는 모든 설치 형태에서 제한된 read-only/no-write 샌드박스 no-op을 실행한다.
- 시스템 헬퍼, 인접한 complete-package 헬퍼, 누락된 헬퍼, 헬퍼/버전
  불일치, 샌드박스 거부, 지원되지 않는 플랫폼과 프로브 timeout을 구분한다.
- 가능한 경우 릴리스 매트릭스에서 시스템 `bwrap`가 없는 공식 단순 Linux tar, 번들 헬퍼가 있는
  complete package와 시스템 헬퍼 레이아웃을 다룬다.
- 정확한 Linux Codex 설치/헬퍼 전제 조건을 운영자 런북에 문서화한다.
- 호환성 근거를 Akra 아카이브 체크섬/멤버 검증 및 소스 테스트 증명과 분리한다.
- Akra가 임의의 운영자 제공 설치 형태에 대한 런타임 지원을 주장하는 경우에만 `StartupDiagnostics`
  샌드박스 준비 상태를 추가한다. `akra doctor`는 제한된 영수증을 표시할 수 있지만, 일반 TUI/Admin
  렌더링은 reachability 또는 doctor 작업을 조용히 실행해서는 안 된다.

**필수 증명**

- 단순 tar 실패를 재현하는 폐기 가능한 릴리스 바이너리 Linux 캡처;
- 해당 Linux 행을 녹색으로 표시하기 전의 complete-package 및/또는 시스템 헬퍼 양성 캡처;
- Akra 소스 SHA, Codex 다이제스트/버전, 플랫폼, 설치 형태, 헬퍼
  출처, 명령 ID, 시간, 종료, 콘텐츠 해시에 연결된 영수증;
- 누락되거나 오래되거나 SHA가 잘못되었거나 부정적인 영수증은 주장된 호환성 행을 실패시킴;
- 이후 제품 경로가 추가되는 경우 선택적인 시작/doctor 프로젝션 테스트;
- 영수증이나 공개 DTO에 비밀, 원시 환경 또는 제한 없는 doctor 페이로드가 없음.

### 프로토콜 네이티브 라이브 실행 레일

기존
[계약](../jcode/gap-matrix.md#p0-프로토콜-네이티브-실시간-실행-레일)을 리뷰 가능한 5개의
하위 슬라이스로 개정한다.

#### P0-A: 터미널 사실

**소유 경계**

- `src/adapter/outbound/app_server/protocol/turn_notifications.rs`;
- `src/adapter/outbound/app_server/connection.rs`, 어댑터 대기 결과와 현재 호출 지점;
- 대화 런타임 이벤트 타입과 `src/core/app/turn_stream.rs`;
- 현재 main 턴 이후, 계획 작업자, 병렬 공식 완료, 프롬프트 로그와 아카이브 소비자만;
- 결정론적 프로토콜 픽스처와 소스-싱크 계약 테스트.

**계약**

- 엄격한 활성 턴 상관관계를 사용하여 `error.error.message`, `codexErrorInfo`,
  `additionalDetails`, `willRetry`, `threadId`와 `turnId`를 파싱한다.
- `willRetry: true`는 제한된 재시도 중 사실을 방출하고 계속 읽는다.
- 재시도하지 않는 오류는 실패한 터미널 후보이지만, 전송에서 허용하는 경우 상관된
  `turn/completed`가 계속 권위 있는 턴 객체다.
- 재시도하지 않는 오류 후 제한된 터미널 유예 기한을 시작한다. 전송이 살아 있는 동안 최종 턴이
  도착하지 않으면 중단되거나 실패 완료를 만들어 내지 말고 알 수 없음/복구 대기 중을 반환한다.
- `turn.status`, 타입이 지정된 오류, 항목 뷰 완전성, 타임스탬프와 기간을 파싱한다.
- `completed`만으로 성공한 터미널 상태가 된다.
- `interrupted`는 중단됨, `failed`는 타입이 지정된 제한 오류가 있는 실패가 된다.
- `inProgress`가 `turn/completed`에 나타나거나 알 수 없는 상태, 필요한 ID 누락 또는 모순되는 오류/상태는
  프로토콜 불일치와 복구 대기 중/알 수 없음이 되며, 절대 성공이 되지 않는다.
- 알림 핸들러에서 연결/어댑터 대기를 거쳐 현재의 모든 호출자까지 타입이 지정된 터미널 영수증 또는
  이에 상응하는 닫힌 결과를 전달한다. Rust `Result::Ok`는 전송 성공이며 절대 터미널 완료 증명이 아니다.
- 해당 영수증이 관찰된 upstream 결과와 별도의 애플리케이션 전달 승인을 유지하게 한다. 가득 찼거나
  연결이 끊긴 싱크는 upstream 사실을 보존하지만 로컬 프로젝션을 확인되지 않음/복구 대기 중으로 표시하며,
  프롬프트 로그 `completed`, 계속 또는 아카이브에 도달할 수 없다.
- 터미널 적용은 라이브 경로 내에서 중복 및 순서가 뒤바뀐 알림에 대해 compare-and-set 방식이며
  멱등적이다. 내구성 있는 재조회/자식 손실 CAS는 계속 복구의 소유 범위다.
- 변경된 파일/세션 관찰은 별도의 사실로 유지한다. 이후 조정을 요청할 수는 있지만 공식 터미널 상태를
  승격하거나 덮어쓸 수는 없다.
- 타입이 지정된 `completed`만 현재 main/계획 계속, 병렬 공식 완료/커밋 준비, 프롬프트 로그 완료 또는
  완료된 아카이브 경로에 들어갈 수 있다.

**필수 증명**

- 모든 상태, retry true/false, 중첩되거나 누락된 오류, 상관관계 불일치, 모순되는 상태/오류,
  중복되거나 순서가 뒤바뀐 터미널과 알 수 없는 상태에 대한 픽스처;
- 라이브 전송이 제한된 유예 기한을 넘기는 재시도하지 않는 오류/최종 턴 없음 픽스처;
- 타입이 지정된 영수증이 성공으로 축소되지 않음을 증명하는 가득 참, 기한까지 차단됨과 연결 끊김
  터미널 싱크 픽스처;
- 모든 라이브 터미널 경로에 대한 핸들러, 연결, 어댑터, Core 리듀서, 프롬프트 로그,
  현재 main/계획 계속, 병렬 공식 완료와 아카이브 단언;
- 정상 완료 및 interrupt-to-interrupted wire 형태에 대해 인증된 릴리스 app-server를 사용한
  폐기 가능한 캡처 하나;
- 실패/중단/알 수 없음이 일반적인 현재 경로 `completed`를 생성할 수 없다는 회귀 테스트.

#### P0-B: 적용된 엔벨로프

- `ThreadPrepared`/활성 턴 애플리케이션 상태를 요청되고 적용된 모델/제공자, 노력 수준, 서비스 티어,
  cwd, 승인, 샌드박스, 권한 프로필, 소스와 관련 환경 분류로 확장한다.
- 요청을 대입하지 말고 누락되거나 알 수 없는 값을 보존한다.
- `model/rerouted`와 설정/상태 변경을 이후 관찰로 사용한다.
- 원시 제공자 구성과 자격 증명을 도메인/공개 DTO에서 제외한다.
- 현재 main, 재개, 계획과 병렬 경로를 증명한다. 복구와 이후 리뷰 응답 소유자는 해당 경로가 구현될 때
  자체 행을 추가한다.

**이 원자적 슬라이스의 구현 근거**

- [`conversation_runtime_envelope.rs`](../../../../src/domain/conversation_runtime_envelope.rs)는
  요청됨, 적용됨, 재라우팅됨, 관찰 출처와 명시적인 프로젝션 격차 의미론을 소유한다.
- [`runtime_envelope.rs`](../../../../src/adapter/outbound/app_server/protocol/runtime_envelope.rs)와
  체크인된
  [`runtime_envelopes.json`](../../../../src/adapter/outbound/app_server/protocol/fixtures/runtime_envelopes.json)
  픽스처는 누락, null, 기본값 적용, 사용 불가, 제한된 알 수 없음과 닫힌 소스 값을 보존하면서
  잘못된 안정 응답을 실패로 닫는다.
- [`conversation_runtime_event.rs`](../../../../src/application/service/conversation_runtime_event.rs)는
  계획 및 병렬 경로에서 사용하는 공유 애플리케이션 프로젝션을 제공하고, Core 리듀서는 app-server
  wire 값을 다시 파싱하지 않고 현재 main/재개 상태를 소유한다.
- 스레드 응답 전의 설정은 응답 시간 순서 경계에서 버리고, 이후 설정/재라우팅/상태 관찰은 정확한
  스레드/턴 상관관계를 사용하며, 관찰 가능한 손실은 터미널 전달을 확인할 수 있기 전에 프로젝션
  격차로 나타낸다.
- 현재 네 경로 모두 안정된 적용 cwd가 보호된 요청 워크스페이스와 같아야 한다. 계획 어댑터와
  애플리케이션 오케스트레이션은 각각 엔벨로프가 누락되거나 거부되거나 해결되지 않은 프로젝션 격차가
  있을 때 권한 변경을 차단하고, 병렬 완료도 동일한 실패 폐쇄 계약을 적용한다.
- 어댑터 로컬 응답 추가 필드는 수정된 `Debug`를 사용한다. 제공자 메타데이터, 협업 설정, 원시 명령
  소스와 자유 형식 구성 경고 본문은 공개 엔벨로프, 프롬프트 출력 또는 병렬 추적 프로젝션에 들어가지 않는다.

이 슬라이스는 이후 표시를 위해 엔벨로프 상태를 유지하지만 적용된 엔벨로프 TUI 표면은 추가하지 않는다.
기존의 제한된 스레드 상태 문구는 이제 수락된 타입 지정 상태 관찰을 프로젝션한다. Admin, CLI,
Telegram, 영속성, 재시작 복구 또는 릴리스 app-server 캡처는 추가하지 않는다. 관찰 시퀀스는 내구성 있는
권한이 아니라 로컬 라이브 어댑터 스트림에 속한다. 기존의 옵트인 프롬프트 로깅은 계속해서 보호된
워크스페이스 cwd와 번들 계획 작업자 스킬 경로를 포함한 명시적인 스킬 입력 경로를 기록한다.
원시 응답 `instructionSources` 또는 런타임 엔벨로프는 기록하지 않는다.

**필수 증명**

- 요청과 적용이 같음, upstream 재정의, 누락/알 수 없는 필드와 잘못된 엔벨로프에 대한 시작/재개
  응답 픽스처;
- 재라우팅/설정/상태 순서와 오래된 턴 상관관계 테스트;
- 요청을 유효 상태로 대체하지 않는 현재 main/재개/계획/병렬 애플리케이션 스냅샷;
- 제공자 구성과 자격 증명이 공개 DTO 또는 로그에 절대 들어가지 않음을 증명하는 수정 테스트.

- 하나의 어댑터 디코더가 안정 종류 18개 전부와 제한된 `Unknown`을 라이브
  `item/started`/`item/completed`와 스냅샷 재생 모두에 대해 프로젝션한다.
- 정확한 스레드, 턴과 항목 ID, 제공자 타임스탬프, 라이브 시작됨/완료됨 또는 스냅샷 관찰됨 단계,
  보고된 결과, 안전한 요약과 FIFO 애플리케이션 시퀀스가 도메인/Core 경계에 도달한다. 스냅샷 재생은
  활성 항목에 대한 완료 경계를 만들어 내지 않는다.
- 256개 레코드 리듀서는 잘림, 유효하지 않은 ID, 알 수 없는 종류, 중복 경계, 시작 전 완료,
  종류 불일치와 타임스탬프 역행 상태를 이들 중 어느 것도 턴 또는 전달 성공으로 승격하지 않고 노출한다.
- 불변 수명 주기 스냅샷은 `Arc`를 통해 공유되며 수명 주기 상태가 변경될 때만 쓰기 시 복사한다.
  로드된 스냅샷 레코드는 같은 스레드의 라이브 리듀서를 복원하고, 다른 스레드 준비는 이를 지운다.
- 모든 라이브 항목 ID와 첫 종류는 별도의 512개 항목, 비축출 SHA-256 원장을 사용한다. 수명 주기
  레코드 축출 후에도 재생은 계속 억제되고, 종류 드리프트는 새 관찰을 유지하면서 더 오래 유지되는
  원장을 통해 스트림을 실패시킨다. 용량 소진은 수명 주기 사실을 유지하고 스트림을 실패시켜 누락된
  최종 텍스트 뒤에 턴이 거짓으로 확인되는 일이 없도록 한다.
- 잘못된 활성 `item/completed` 페이로드는 최종 텍스트나 도구 사실이 폐기된 턴을 이후의 터미널 알림이
  확인할 수 있기 전에 스트림을 실패시킨다. 타임스탬프가 역행한, 처음으로 고유하게 식별된 완료는
  이상을 유지하면서도 페이로드를 전달한다.
- 파일 변경은 타입이 지정된 `Completed` 결과에 대해서만 변경된 경로와 도구 활동 효과를 생성한다.
  실패, 거부, 진행 중, 알 수 없음과 재생된 파일 변경은 수명 주기 사실로 남는다.
- 소스 매니페스트는 현재의 모든 항목 필드를 보존, 제한 수정 또는 명시적 무시로 분류하고, 항목 변형,
  필드, 닫힌 상태와 알림 메서드를 체크인된 생성 스키마와 비교한다.
- 원시 프롬프트, 추론, 계획, 명령/출력/diff/경로/쿼리/이미지 본문, 도구 인수/결과, 협업 프롬프트와
  리뷰 텍스트는 수명 주기 프로젝션이나 프롬프트 로그에 들어가지 않는다.
- `EnteredReviewMode`와 `ExitedReviewMode`는 런타임 관찰로만 남는다. Review Center, GitHub 리뷰,
  계획, 검증, 병합 또는 전달 권한을 변경하지 않는다.

이 슬라이스는 의도적으로 점진적 델타 처리, 풍부한 수명 주기 레일, Admin/CLI/Telegram 프로젝션,
병렬 활동 영속성, 내구성 있는 재시작 복구 또는 릴리스된 Akra 런타임 캡처를 추가하지 않는다.
해당 소유자는 app-server JSON을 다시 파싱하지 않고 이후에 이 타입 지정 계약을 사용한다.

#### P0-C2: 제한된 점진적 활동

- 운영자 결정을 이끄는 경우 명령 출력/터미널 상호작용, 패치/출력 델타, 턴 diff, 계획,
  토큰/컨텍스트 사용량, 조정/가디언, 압축과 재라우팅 사실을 추가한다.
- 항목 경계, 터미널, 승인, 오류 또는 지연/과부하 마커를 절대 병합해 없애지 않으면서 상관된 항목별로
  고빈도 델타를 병합한다.
- 점진적 페이로드 클래스별로 크기, 잘림, 수정, 유지와 재생 정책을 정의한다.
- 전체 diff/출력 드릴다운을 제한된 요약 상태와 분리한다.

**필수 증명**

- 코드로 추적되는 정확한 유지 페이로드와 백로그 제한을 갖춘 고정된 고빈도 텍스트, 명령 출력,
  패치, diff, 계획, 토큰과 다중 에이전트 스트림. 할당자/RSS 측정은 이후 네이티브 성능 아티팩트의
  소유 범위다.
- 터미널 및 승인이 살아남음을 증명하는 병합 순서와 연결 끊김/과부하 테스트;
- 컨텍스트 압박과 diff 요약/제한 상세 픽스처. 대화형 전체 드릴다운은 P0-D의 소유 범위다.
- 알 수 없는 델타와 과대/비 UTF-8 페이로드 테스트.

**이 슬라이스에서 구현됨**

- 하나의 엄격한 어댑터 매니페스트가 점진적 알림 14개를 처리됨으로, 더 이상 사용되지 않는
  `item/fileChange/outputDelta`와 `thread/compacted`를 명시적 무시로, 모델 안전 버퍼링/검증을
  스키마로 검증된 진단 전용 입력으로 분류한다.
- 정확한 스레드/턴/항목 상관관계와 P0-C1 항목 종류/완료 원장이 항목 활동을 게이트한다. 누락된 경계,
  종류 드리프트 또는 완료 후 활동은 스트림이 실패로 닫히기 전에 유지된다. 오래된 범위는 애플리케이션
  시퀀스를 소비하지 않고 삭제된다.
- 알 수 없는 점진적으로 보이는 항목, 턴과 턴 상관 스레드 메서드는 제한되고 수정된 메서드 레이블과
  페이로드 바이트 수만 유지한 뒤 실패로 닫힌다. 닫힌 계획 상태, 패치 종류와 검증 열거형도 알려진
  상태로 조용히 바뀌지 않고 명시적인 스키마 결정을 요구한다.
- 타입이 지정된 페이로드는 에이전트 초안, 명령 꼬리와 터미널 상호작용 수, 패치 상세, 턴 diff
  요약/상세, 계획, 토큰/컨텍스트 압박, MCP 진행, 추론/계획 수, 조정 크기와 가디언 경고를 다룬다.
  상세 제한은 4 KiB 가디언 문구부터 2 MiB 에이전트/diff 상세까지이며, 전체 동적 유지 상태는
  64개 레코드와 8 MiB다. 누적 토큰 합계는 최신 활성 컨텍스트 내역을 포함해야 하며, 압축 후에는
  해당 최신 합계만 컨텍스트 압박을 결정한다.
- 불투명한 검증 완료 배치는 단조 증가 시퀀스와 상관관계를 보존한다. 페이로드 잘림과 완전히 삭제된
  관찰은 별도의 카운터를 가지며, UTF-8 접두사/꼬리 제한은 정확하고 유지된 모든 상세/ID의 Debug
  출력은 수정된다. 배치 및 게시물 간 프로젝션 병합은 유지 활동을 변경하기 전에 카운터 또는 페이로드
  계산 오버플로를 거부한다.
- 애플리케이션 메일박스는 이벤트 8개의 제어 수용 예산과 순서가 지정된 점진적 세그먼트를 유지한다.
  Core 수신은 16개의 제어 수용과 최대 17개의 점진적 세그먼트로 정책을 반복한다. 인접하고 상관된
  게시물만 병합된다. 모든 제어는 정확한 순서 경계로 유지되며, 각 대기 계층에는 추적되는 8 MiB 상세
  제한 하나가 있다. 오래된 상세는 경계를 넘거나 제거하지 않고 동일한 위치의 이력 전용 마커가 된다.
  더 새로운 Core 세대는 오래된 점진적 백로그를 정리하고, 현재 세대 세그먼트 수용 실패는 조용한
  손실이 아니라 터미널 스트림 실패가 된다.
- Core는 각 배치를 불변 `Arc` 프로젝션에 직접 사용하고, 이력 전용 격차를 적용하며, 오래되거나
  상관되지 않은 배치를 거부하고, 각각의 새 턴/스레드에서 재설정한다. 프로덕션 TUI 폴링은 COW
  스냅샷 벡터를 유지하는 대신 한 번에 하나의 Core 결과를 적용한다. 라이브 에이전트 버퍼는 타입이
  지정된 프로젝션과 동기화된다. 제거된 레거시 델타 열거형은 더 이상 이 경로를 우회할 수 없다.
- 점진적 상세는 옵트인 프롬프트 출력 로그에서 제외되며 직렬화 또는 Admin/CLI/Telegram 영속성 경로가
  없다. 활성 턴 리듀서는 카운팅 라이터를 통해 조정 및 알 수 없는 페이로드의 크기를 계산한다.
  응답/스트림 인계 전반에 유지되는 초기 알림은 별도의 제한된 대기 큐 바이트 예산 아래에서 기존 JSON
  값을 한 번 다시 인코딩할 수 있다.

결정론적 증명에는 100,000개 게시물 리듀서/메일박스 스트림, 고정된 고빈도 에이전트, 명령, 패치,
diff, 계획, 토큰과 다중 에이전트 리듀서, 정확한 `progress -> control -> progress` 순서,
애플리케이션과 Core 수신에서 2 MiB 점진적 세그먼트 9개와 번갈아 배치된 제어 8개, 승인/터미널 생존,
항목 경계 드리프트 실패, 처리된 메서드 14개 전부, 스키마 형태 지문, 청크 경계를 넘는 정확한 명령줄
계산, 과대 UTF-8 잘림, 이름 변경 목적지를 포함한 정확한 소스/유지/손실 바이트 계산, 게시물 간
오버플로 거부, 압축 후 및 스키마 최대 컨텍스트 압박, 비 UTF-8 전송 거부, 이력 전용 Core 적용,
오래된 세대 정리와 비밀 카나리아가 포함된다.

P0-C2 커밋에서 이 슬라이스는 의도적으로 활동 레일 또는 Diff/Output 인스펙터를 추가하지 않았다.
P0-D1은 이후 `b53559ca`에서 제한된 요약 레일을 추가했고, P0-D2는 `594859a6`에서 일시적으로 유지되는

Akra 런타임 활동 캡처와 비교 성능 근거는 이들 슬라이스와 분리되어 있으며 여전히 없다. 더 이상 사용되지
않는 압축은 두 번째 점진적 사실 대신 P0-C1 `ContextCompaction` 항목으로 나타낸다. 모델 재라우팅은
계속 P0-B 적용된 엔벨로프의 소유 범위다.

#### P0-D: Core 및 TUI 투영

  일급 환경 4개 모두를 동일한 정확한 소스 후보와 플랫폼별 바이너리 다이제스트에 연결한다. 실제 Codex
  app-server 세션은 입력, 활성/최종 상태, 도움말/다시 그리기, 물리적 축소/복원, 지우기/재설정,
  세션 복원과 정상 종료를 다룬다. 이는 공유 프리미티브 변경에 대한 E1-E4 수동 리뷰어 의무를 충족한다.
- 이 캡처들은 계속 `supplemental-unmatched`이며 `terminal-baseline`에 포함되지 않고 릴리스된 Akra
  런타임 활동 근거가 아니다. P0-D는 해당 릴리스된 Akra 런타임 활동 캡처에 대해서만 부분 상태다.
  이 슬라이스들은 Admin/CLI/Telegram 프로젝션, 병렬 또는 내구성 있는 영속성, 재시작/조정 복구 동작
  또는 비교 지연 시간/RSS를 주장하지 않는다.

**필수 증명**

- Core 리듀서 테스트와 좁음/넓음 및 긴 값 TUI 스냅샷;
- vt100/ANSI 프레임 단언과 하나 이상의 실제 터미널 캡처;
- diff/출력 드릴다운, 크기 조정, 입력, 승인 우선순위와 호스트 스크롤백 회귀 테스트;
- 고정된 P0-C2 스트림 아래에서 레이아웃 이동이나 제한 없는 렌더링 작업이 없음.

  사용하지 않는다.

### 제한된 로컬 데몬 UDS 실현 가능성 실험

복구 정확성이 녹색인 후에만 자체 근거 worktree/PR에서 이를 실행한다. 이는 P0 제품 토폴로지 변경이 아니다.

- 동일한 버전, 인증 상태, 워크스페이스, 워크로드와 전체 프로세스 트리 계산을 사용하여 현재 Akra
  자식/JSON 경로와 공식 로컬 데몬 UDS 경로를 비교한다.
- 호환되는 기본 구성, 재생할 수 없는 재정의 폴백, 누락되거나 오래된 소켓, 클라이언트 연결 끊김,
  데몬 종료, 업데이터 재시작, app-server 버전 드리프트와 프로세스 정리를 다룬다.
- 이 스냅샷에서 데몬이 실험적이고 Unix 전용이며 재부팅 후 유지되지 않음을 기록한다.
- 모든 실패 사례에서 터미널/복구 사실이 살아남도록 요구한다.
- 명시적인 도입/거부/연기 결정을 생성한다. 긍정적인 결과도 이후에 별도로 리뷰되는 제품 계약 없이
  프로덕션 토폴로지를 변경할 수 없다.

### 고정 소스 검증 근거

기존
[계약](../jcode/gap-matrix.md#p0-고정-소스-검증-증거)을 유지하고 런타임 및 릴리스
소비자를 추가한다.

- P0-A가 `completed`라고 판단할 때만 런타임 턴 성공이 후보 인계를 승인할 수 있다. 실패, 중단,
  복구 대기 중, 알 수 없음, 중복 또는 의미론적으로 분류되지 않은 터미널 사실은 검증 준비 및
  전달 준비 전환을 차단한다.
- 성공한 검증 명령은 실패한 공식 턴을 완료된 작업자 실행으로 소급해 변환하지 않는다.
- 정확한 소스 SHA와 검증 근거 옆에 런타임 터미널 출처를 기록한다.
- 태그 워크플로가 npm 또는 GitHub Release 상태를 변경하기 전에 해당 태그 SHA에 연결된 신뢰할 수 있는
  네이티브 소스 테스트 영수증을 요구하거나, 분리된 정확한 SHA 체크아웃에서 권위 있는 네이티브 검사를
  다시 실행한다.
- 누락, 실패, 오래됨, 잘못된 SHA 또는 잘못된 정책 영수증은 릴리스 게시를 차단한다.
- 소스 테스트 증명, Codex 설치 호환성 증명과 아카이브 바이트/멤버/체크섬 증명을 별도 게이트로 유지하여
  어느 하나도 다른 하나를 대신하지 못하게 한다.
- 중복 의존성 잠금 백로그를 만들지 말고 argv 회귀 테스트를 통해 기존 `cargo --locked` 릴리스 및
  PR 동작을 보존한다.

## 기존 P0/P1 수정 사항

### 명령 및 권한 선택 충실도

기존 OpenCode
[계약](../opencode/gap-matrix.md#p1-명령-및-권한-선택-충실도)을 수정하고 확장한다.

- P0-A 터미널 진실과 P0-C1 `item/started` 소유권에 의존한다.
- 기존의 권위 있는 신뢰/프로필 선택 없이 일반 workspace-write 세션을 시작하기 전에 안정적인
  `permissionProfile/list`를 조회하고, 허용된 제한적 요약만 제시하며, 선택을 정확히 표현할 수 없는
  경우 읽기 전용을 유지한다.
- 일반적인 `experimentalApi: false` 경로에서는 정확한 레거시 `sandbox` 대응값이 있는 명시적으로
  허용 목록에 포함된 기본 제공 프로필 ID만 매핑하고, 안정적인 범용 `config.default_permissions`
  탈출구를 명시적으로 금지한다. 명명된/사용자 지정 타입 선택과 `activePermissionProfile` 출처에는
  별도로 리뷰된 실험적 옵트인이 필요하다. 탐색이나 기존 구성 기본값 때문에 Akra가 타입 없는
  재정의를 보내거나 적용된 프로필 ID를 조작해서는 안 된다.
- Akra를 실행한 것만으로 암묵적인 재사용 가능 신뢰 결정을 영속화해서는 안 된다.
- 프로젝트 신뢰/프로필 범위, 출처, 시간과 요청/적용된 샌드박스를 계속 표시한다. 프로필 변경은 명령
  하나의 승인과 별개이며 더 넓은 범위에는 확인이 필요하다.
- 명령/cwd를 생략하는 공식 네트워크 전용 승인 페이로드를 허용하되, 자체 네트워크/호스트/프로토콜
  사실과 일반적인 스레드/턴/항목/요청 상관관계를 요구한다.
- 누락/null 레거시 `availableDecisions` 폴백을 비어 있음, 잘못된 형식 또는 알 수 없는 값이 섞인
  배열과 별도로 보존한다.
- 대기 중 요청을 도착 순서로 저장한다. 자사 모달에서 발생할 수 있는 LIFO 경계 사례를 복제하지 않는다.
- 모든 라이브 로컬 상태에서 일치하는 `serverRequest/resolved`를 `remote_cleared`로 수락하면서 응답
  쓰기 전 수명 주기 정리를 포함한 마지막 로컬 상태를 보존한다.
- `remote_cleared`는 수명 주기 정리를 포함해 업스트림에 더 이상 대기 중 요청이 없다는 것만 증명한다.
  수락/거절 소비나 도구 효과를 증명하지 않는다.
- 상관관계가 있는 권위 있는 항목/턴 결과만 효과를 확정한다.
- 쓰기 전 정리, 쓰기 후 정리, 중복/불일치 해결, 연결 끊김, 타임아웃과 늦은 UI 동작은 명시적인
  출처를 유지하고 결정 결과를 조작하지 않는다.

상태 사다리는 다음과 같다.

```text
pending -> locally_decided -> write_attempted -> write_confirmed
pending | locally_decided | write_attempted | write_confirmed
-> remote_cleared -> authoritative item/turn outcome
```

`write_attempted` 이후의 모든 전이는 불확실한 상태로 남을 수 있다. 파일 승인과 타입 지정 사용자/MCP
폼은 기존 P2 슬라이스에 그대로 둔다.

### Admin 운영 지표

기존
[계약](../jcode/gap-matrix.md#p1-admin-운영-지표)을 수정한다.

- 직접 런타임 시간, Akra 오버헤드, 모델/네트워크 시간, 검증 시간, 리뷰 대기, 통합 시간과 정리 시간을

### 병렬 현재 활동 및 완료 근거

[병렬 현재 활동 엔벨로프](../agent-canvas/gap-matrix.md#p0-병렬-현재-활동-envelope)와

현재 활동 이후의 별도 PR로 유지한다. 영속화된 레인/전달 의미론을 소비하며 TUI 프레임이나 런타임
산문에서 진행 상황을 추론해서는 안 된다.

- 타입 지정 완료에서만 후보 인계를 허용한 다음, 보고서, 커밋, 동결, 검증, 게시, PR, 리뷰, 검사,
  통합, 원격 검증과 정리를 별개로 유지한다.
- 실패/중단/알 수 없음/복구 대기 중인 공식 턴은 작업자 요약이 성공을 주장하더라도 준비 또는 통합
  상태가 될 수 없다.
- 변경된 파일, 커밋 또는 이후 검증은 별개의 사실이며 공식 런타임 터미널 결과를 다시 쓸 수 없다.
- 명시적인 자율 리뷰/검사/PR 우회 정책을 리뷰 완료로 집계하지 말고 노출한다.

## 새 P1 작업 단위: 공식 모델 기능 투영

이는 업스트림 감사에서 도입하는 유일한 새 제품 슬라이스다. 적용된 엔벨로프 진실이 P0-B에 먼저
도착하며, 이 슬라이스는 정적 선택을 공식 기능으로 대체한다.

**소유 경계**

- app-server 어댑터가 구현하는 새로운 좁은 아웃바운드 `ModelCatalogPort`;
- 애플리케이션 모델 카탈로그 서비스와 캐시 상태;
- 확장 가능한 도메인 모델/노력/기능 값;
- 기존 TUI 모델/추론 오버레이와 시작 진단;
- TUI 경로 완료 후에만 공유 읽기 전용 Admin/CLI 프로젝션.

**계약**

- 초기화 후와 명시적인 새로 고침/무효화 신호에서 안정적인 `model/list`를 호출한다.
- 제한된 페이지/항목 한도, 취소와 반복 커서 감지를 사용해 불투명 커서 페이지를 소비한다. 부분 카탈로그는
  암묵적으로 권위 있는 선택기가 아니라 불완전/오류 상태로 남는다.
- 모델 ID, 표시 레이블, 기본값, 지원되는 추론 노력, 입력 모달리티, 서비스 티어와 제한된 기능/상태
  필드를 보존한다.
- 노력은 도메인 열거형을 닫는 대신 공식 `max`, `ultra` 또는 이후 값을 포함하는 확장 가능한 검증된
  값으로 표현한다.
- 명시적인 사용자 지정 ID 워크플로를 별도로 설계하지 않는 한 광고된 모델/노력/티어 조합만 선택한다.
- 요청된 선택과 P0-B의 실제 적용/재라우팅 상태를 명확히 구분해 표시한다.
- 일시적인 새로 고침 실패 시 마지막 카탈로그를 최신성/오류 상태와 함께 유지한다. 모델을 발명하거나
  이전 선택을 현재 선택으로 제시하면서 조용히 폴백하지 않는다.
- 카탈로그를 변경할 수 있는 app-server 인스턴스/버전/계정/구성 사실별로 캐시 범위를 지정한다.
- 제공자 전송, 자격증명, 가격과 모델 실행은 업스트림에 둔다.
- 일반 초기화에서 실험적 기능을 비활성화하는 동안 안정 기능 전용을 유지한다.

**사용자 결과**

운영자는 실행 중인 공식 Codex가 실제로 광고하는 모델과 추론 값 중에서 선택하고, 업스트림이 다른
값을 적용하거나 재라우팅하는 때를 확인할 수 있다.

**필수 증명**

- 비어 있음, 기본값, 알 수 없는 노력, max/ultra, 티어/모달리티, 페이지네이션, 반복 커서, 한도 소진,
  중복/잘못된 형식, 새로 고침과 일시적 실패에 대한 가짜 `model/list` 픽스처;
- 런타임 ID로 범위가 지정된 애플리케이션 캐시/무효화 테스트;
- 시작/재개/턴 요청 직렬화와 적용/재라우팅 조정;
- 긴 모델 ID와 사용 불가/오래됨 상태를 포함한 좁음/넓음 TUI 스냅샷;
- 도메인, Admin, 로그 또는 영속성에 제공자 자격증명/원시 구성이 없음;
- 고정된 버전에 대한 릴리스 app-server 카탈로그 캡처 하나.

## 기존 P2 수정 사항

### 공식 세션 검색, 출처 및 포크

기존
[공식 세션 검색 및 출처](../jcode/gap-matrix.md#p2-공식-세션-검색-및-출처)와 OpenCode
포크 의존성을 수정한다.

- 목록 요청에 커서를 추가하고 제한된 취소/중복 처리로 모든 페이지를 소비한다.
- 안정적인 cwd/검색/출처/아카이브 필터를 사용하고 다음 커서/오류/최신성을 보존한다.
- 세션 ID, 포크 원본, 부모 스레드, 출처, 에이전트 경로/별명/역할, Git 정보, 임시/아카이브/기록과 턴
  항목 뷰 완전성을 유지한다.
- 포크 탐색을 구현하기 전에 계보를 노출한다.
- 포크 ID와 소스/턴 경계를 명시하고 전달 완료를 상속하지 않은 채 새 공식 스레드를 Akra 계획/전달
  컨텍스트에 연결한다.
- TUI 카탈로그/상세를 먼저 프로젝션한 다음 읽기 전용 Admin 상세를 프로젝션한다.
- 실험적 `thread/turns/list` 또는 `thread/items/list`를 Akra가 `experimentalApi: false`로
  초기화되는 동안 약속하지 않는다.
- 사용 불가한 상세를 완전히 비어 있는 기록과 구분한다.

### 파일 승인 및 타입 지정 양식

검사 가능한 파일 변경 승인과 타입 지정 사용자/MCP 추출에 대한 기존 P2 소유권을 유지한다. 이는
P0-C1 항목 소유권, 승인 `remote_cleared` 상태, 터미널 복구와 알려진 카나리 불변식에 의존한다.
제한된 애플리케이션 타입 없이는 원시 업스트림 폼이나 패치 DTO가 공개 표면에 들어갈 수 없다.

## 성공 감사

Akra는 해당하는 모든 진술이 참일 때만 업스트림 기준선을 처리했다고 주장할 수 있다.

- 정확한 안정 및 실험적 스키마/기능 계약이 독립적으로 고정되어 있다.
- 재시도 중 오류는 계속되고, 실패/중단은 절대 완료가 되지 않으며, 알 수 없음은 절대 전달하지 않는다.
- 요청/적용/재라우팅된 런타임 상태가 표시되고 상관관계가 있다.
- 모든 공식 항목/상태에 명시적인 제한적 프로젝션 결정이 있다.
- TUI, Admin, CLI, Telegram, 병렬, 프롬프트 로그, 검증과 전달 경로가 터미널 진실을 공유한다.
- app-server 자식과 모델 셸 환경이 명명된 카나리 매트릭스를 통과한다.
- 원시 app-server 호스트 API가 공개 원격 표면에 없다.
- 지원된다고 주장하는 모든 Codex 설치 형태에 새로운 샌드박스 도우미 호환성 영수증이 있다.
- 성능 주장에는 동일 머신의 대화형 원시 근거와 완전한 프로세스 트리 범위가 있다.
- 승인 로컬 쓰기, 원격 지움과 권위 있는 효과는 별개로 유지된다.
- 공식 모델 선택지는 실행 중인 안정 카탈로그에서 가져온다.
- 세션 페이지 탐색, 계보와 포크는 비활성화된 실험적 메서드에 의존하지 않는다.
- Codex 런타임 에이전트/리뷰/계획/목표는 절대 Akra 계획, 리스, 검증, GitHub 리뷰, 통합 또는 정리
  권한을 대체하지 않는다.
- 모든 구현 행은 자체적으로 리뷰된 worktree/commit/push/PR/rebase-merge를 통해 반영되고 완료된
  worktree는 제거된다.
