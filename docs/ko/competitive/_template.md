# 제품 분석 템플릿

[English](../../competitive/_template.md)

검토 전에 모든 자리표시자를 교체합니다. 적용할 수 없는 절은 짧은 이유를 남긴 경우에만
삭제합니다.

체크아웃이 공개되어 있는지, 로컬에서 사용할 수 있는지, 변경 사항 없이 깨끗한지 밝힙니다. 비공개
소스 제품은 사용한 정확한 바이너리, 버전, 공개 문서를 대신 나열합니다.

## 근거 규율

상위 [근거 규칙](README.md)에 따라 각 조사 결과가 `verified`, `documented`, `proposed`,
`inferred`, `unverified` 중 어디에 속하는지 정의합니다. 제품의 `evidence.md` 원장을 연결합니다.

## 핵심 결론

다섯 문장에서 열 문장으로 다음을 작성합니다.

- 제품을 선택할 실제 이유를 밝힙니다.
- Akra에 가장 강한 위협 두세 가지를 명시합니다.
- Akra가 활용해야 할 구조적 약점을 밝힙니다.
- Akra가 채택하고 거부하고 차별화해야 할 항목을 제시합니다.

## 제품과 대상 사용자

- 주요 운영자와 작업 흐름
- 제품 인터페이스
- 배포 방식과 지원 플랫폼
- 중요한 경우 가격, 인증, 공급자에 관한 가정

## 아키텍처

- 런타임 권한
- 프로세스 및 클라이언트/서버 토폴로지
- 영속성과 프로토콜
- 모듈/패키지 경계
- 재연결, 재개, 장애 복구

현재 구현과 제안된 아키텍처를 구분합니다.

## 하네스와 컨텍스트

- 공급자/모델 라우팅
- 도구, MCP, 스킬, 명령, 플러그인, 훅
- 컨텍스트 구성, 압축, 세션 검색, 메모리
- 권한과 무인 실행 규칙

## TUI와 UX

- 최초 실행과 제출 흐름
- 대화 기록과 도구 활동 표시 방식
- 세션 탐색과 병렬 작업 가시성
- 프롬프트 편집, 명령 팔레트, 승인, 변경 내용 비교, 복구
- 좁은 터미널, 스크롤 기록, 크기 변경, 입력, 렌더링 동작

## 관리자 및 원격 인터페이스

- 웹/데스크톱/관리자/모바일 상태
- 동일한 애플리케이션 상태를 공유하는지 또는 런타임 로직을 중복하는지
- 운영 지표, 감사 이력, 원격 작업

## 병렬 작업

- 격리 단위
- 할당과 조정
- 충돌과 파일 소유권
- 완료 증명, 통합, 검토, 정리

## 성능

게시하거나 재현한 각 수치에 다음을 포함합니다.

- 정확한 바이너리 버전과 커밋
- 머신과 터미널 환경
- 웜/콜드 및 인증/비인증 상태
- 프로세스 트리 경계
- 실행 횟수와 원시 표본
- 측정 정의

지원 근거가 없는 주장은 `unverified`로 표시합니다. 서로 호환되지 않는 지표를 하나의 점수로
정규화하지 않습니다.

## 품질과 위험

- 테스트 및 검증 구조
- 릴리스 관문
- 아키텍처 및 규모 부채
- 보안과 자격 증명 노출면
- 실제로 출시되었음을 입증할 수 없는 문서화된 설계

## 결정

### 채택

Akra의 Codex 우선 경계에 맞는 패턴과 이를 소유할 Akra 모듈을 적습니다.

### 거부

런타임 권한을 중복하거나 안전성을 약화하거나 제품 이점 없이 인터페이스만 추가하는 패턴을
적습니다.

### 차별화

Akra가 의도적으로 더 강하거나 더 좁은 대안을 제공해야 할 역량을 적습니다.

## 구현 단위

수용한 각 구현 단위에는 다음이 필요합니다.

| 우선순위 | 구현 단위 | 소유 경계 | 사용자 결과 | 필수 증명 |
| --- | --- | --- | --- | --- |
| `P0` | `<name>` | `<files/modules>` | `<observable result>` | `<tests/benchmark/capture/state>` |

여러 인터페이스에 걸친 주장의 한 계층만 다루는 단위 테스트로 구현 단위가 완료되었다고 판단하지
않습니다.

## 갱신 조건

분석을 무효화할 제품 릴리스, Akra 변경, 누락된 실험을 나열합니다.
